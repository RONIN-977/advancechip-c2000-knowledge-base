# 335 升级完整流程核验（2026-09-29）

本次继续修正两项 BOOT 问题：

1. `CsmUnlock()` 的成功返回值是 1；Flash API 的 `STATUS_SUCCESS` 是 0。此前混用，正常解锁反而使 `apiReady=0`，导致 0x70 在擦除前返回 1。现在按 1 判断解锁成功。
2. `UpgradeWatchdog()` 原来用 EDIS 结束，破坏 Flash API 调用方的 EALLOW。配套 B 版库 `_Fl28x_EnterCmdMode` 在回调之后继续写 Flash 控制寄存器；现在回调在 RAM 内用 PUSH ST1 / POP ST1 保存恢复状态，不干扰调用方的保护写使能和中断屏蔽。

两种晶振 BOOT 的工程、OUT/MAP 和上位机目录内的 BOOT 副本均已更新。版本仍为 201，具体文件以 `SHA256SUMS.txt` 为准。APP 正文仍为 5650 字节，当前 APP 和上位机程序可继续使用。

## 实板复测

用户已确认此前 SCI 修正后能够进入升级模式并读取 BOOT 201。本次请用 JTAG 重新烧入 `335固件/30m/boot/Debug/AVP32F335_BOOT_30MHz.out`，再使用现在的 APP OUT 进行升级。设置仍为 SCI-A、115200/8N1。

依次观察：读取版本 201 → 0x70 擦除成功 → 写入进度 → MD5 成功 → 启动 APP → 再次进入 BOOT 并重复升级。物理擦写、复位启动、断电中断恢复以及 33.3m 板卡仍待实板记录。

## 软件复现入口

资料库主工程 `AVP32F335/335SCI统一升级_V201`：`tests/run-firmware-tests.py`、`tests/run-sci-runtime-tests.py`、`tests/verify-maps.py`。前两者需要 Python unicorn、pyelftools 和 TI ARM Clang；MAP/反汇编检查使用 TI C2000 20.2.0.LTS。
