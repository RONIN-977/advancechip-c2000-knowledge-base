# AVP32F335 SCI-A V201 接线与首次烧录

此版本与原 F280039C 上位机合并。选择 F280039C 后沿用其原协议、CAN 参数和 OUT 自动转换；选择 AVP32F335 后使用原 335 SCI 帧格式及本次配套 V201 BOOT/APP。本次未提供 335 CAN。

## 接线与使用

使用与板上电平匹配的 USB UART，交叉连接 TX→GPIO28/SCIRXDA、RX←GPIO29/SCITXDA，并连接 GND。不要将 RS232 电平直接接到 MCU。上位机设置为 **115200、8N1、无流控**。

1. 核对板上晶振是 30.000 MHz 还是 **33.300 MHz**，选择同名目录内的 BOOT 和 APP。33.300 MHz 版本不是 33.333 MHz 版本。
2. 首次用 CCS/JTAG 烧录 `AVP32F335_BOOT_*.out`，按原开发板配置使用 Flash 启动。该步骤替换 A 扇区 BOOT；新 BOOT 的版本必须读到 **201**。原始 64 KB BOOT 会在上位机开始擦除前被拒绝。
3. 复位后打开统一上位机，选择 AVP32F335 → USB 串口 · SCI → 实际 COM 号，点击“读取设备”。空 APP 会持续等待；已有有效 APP 时，启动后的约 5 秒内读取设备可保持 BOOT。
4. 选择配套 `AVP32F335_APP_*.out`，点击“开始升级”。上位机自动提取 Flash 装载段、填充空洞、分包发送并校验；无需手工生成 BIN。
5. 成功后自动启动 APP；也可取消“成功后复位”，确认日志后点击“复位启动”。后续可从配套 APP 点击“进入升级”。

若同时通过 JTAG 烧 APP，APP 下载只能擦 H～B，须保留 A 扇区的 BOOT。优先采用“先 JTAG 烧 BOOT，再串口升级 APP”的流程。

升级取消或失败后不要立即复位，等待当前 Flash 操作完成，再从头升级。没有完成整包 MD5 和有效标志提交的新镜像不会启动。擦除命令超时上限 120 秒；关闭上位机不能中止 MCU 正在执行的 Flash API。

## 分区及客户 APP 合入

全部地址为 **16 位字地址**：

| 用途 | 地址 | 规则 |
|---|---|---|
| APP 正文 / H～B | 0x300000～0x337FFD | 最大 458748 字节，即 448 KB 减 4 字节 |
| APP codestart | 0x300000，2 个字 | 按配套链接文件重新链接 |
| 有效标志保留区 | 0x337FFE～0x337FFF | BOOTFLAG 段值 0x00AA，独立处理，升级结束后才写入 |
| BOOT / A | 0x338000～0x33FFFF | 串口升级不擦 A；启动分支 0x33FFF6；含原 CSM 布局 |

当前输入格式为提供工程使用的 C28x little-endian COFF v2 OUT。加载器使用 **LOAD 地址**，RAM 函数仍取其 Flash 装载数据；BSS、COPY/debug、DSECT 和 NOLOAD 不发送。正文空洞填 0xFFFF。段重叠、缺少 codestart/BOOTFLAG、截断文件及 BOOT/CSM/OTP/RAM 装载段会被拒绝。原 0x307FFE 标志布局的 APP 必须重新编译。

将客户业务代码合入配套 APP 时，保留 `Main/UpgradeConfig.h`、`common`、SCI-A 中断和主循环 `RemoteModbus_MsgProcess()` / `UpgradePendingAction()`。保持 APP 的 `ramfuncs` 装载于 Flash、运行于 RAML1，保留链接文件的 BOOTFLAG 和 CSM DSECT 设置。不要把 BOOT 的 Flash API、CSM 段复制到升级 APP。

## 晶振配置与编译

编译宏 `BOARD_OSC_HZ=30000000UL` 或 `33300000UL`。未定义时默认为 30 MHz。`firmware/common/UpgradeConfig.h` 根据宏同步 PLL/DIVSEL、LSPCLK、SCI BRR、定时器和 CPU_RATE；BOOT 使用 3/3/5、APP 使用 5/5/8 的 Flash PAGE/RAND/OTP 等待。切换时钟前从 RAM 将等待设置为 5/5/8，再切 PLL，最后设置目标等待。

| 晶振 | BOOT SYSCLK / BRR / 实际波特率 | APP SYSCLK / BRR / 实际波特率 |
|---|---|---|
| 30.000 MHz | 60 MHz / 32 / 113636.36 | 150 MHz / 40 / 114329.27 |
| 33.300 MHz | 58.275 MHz / 31 / 113818.36 | 149.85 MHz / 40 / 114214.94 |

上位机均使用 115200，BRR 是最接近的整数分频；实际容差和切换稳定性待两种晶振实板验收。BOOT 沿用已核对的 B 版 `Flash28335_API_V210.lib`，SHA256 为 `2FD4073BE476E48247CD9CB29D0D9FF11A20777D08E21202253156FCDC864831`。

在 `AVP32F335/335SCI统一升级_V201` 目录执行：

```powershell
python build-firmware.py --compiler C:\ti\ti-cgt-c2000_20.2.0.LTS
```

一次生成 `build/30MHz` 和 `build/33.3MHz` 下的四个 OUT、MAP 和 build.log。脚本使用相对路径兼容旧编译器。CCS 工程可导入；在 CCS 中选择 30MHz / 33.3MHz 配置，保留相邻 common 目录；本次已验证命令行编译，未验证 CCS IDE 导入。

## SCI 协议

保留 0xCC 帧头、原长度字段 `(帧字节数 << 3)`、原 CRC8（反射多项式 0x8C，初值零）、CRC16（反射多项式 0xA001，初值零）、小端命令/序号。请求 flags=1，BOOT ACK=0x89，APP ACK=0x81。帧最大 160 字节。

| 命令 | 请求 / 应答有效载荷 |
|---|---|
| 0x01 | 空 / 26 字节版本信息，BOOT uint32 在偏移 18，APP uint32 在偏移 22 |
| 0x02 | 空 / 状态；APP 看门狗复位，BOOT 仅在有效标志存在时启动 APP |
| 0x70 | uint32 总字节数 / 状态 + uint16 包容量 128 |
| 0x71 | 空 / 状态模式 0=APP、1=BOOT + 两保留字节；首字节不是通用错误码 |
| 0x72 | 空 / 状态；APP 排空 ACK 后跳 BOOT，BOOT 保持升级模式 |
| 0x73 | uint32 包索引 + uint16 长度 + 1～128 字节 / 状态 + 原包索引；长度须为偶数 |
| 0x74 | 16 字节 MD5 / 状态；完整接收、逐包回读、整包 Flash MD5 通过后提交标志 |
| 0x75 | 空 / 状态；BOOT 排空 ACK 后启动有效 APP |

通用状态 0=成功、1=Flash/API 错误、3=MD5 不一致、5=参数/状态错误。包地址固定 `0x300000 + index * 64` 字；末包可短，其余必须 128 字节。同一完整请求重发返回缓存应答，避免重复擦除、写入或提交。上位机检查 ACK 命令、序号、包索引、BOOT 状态及错误码，超时最多重试两次。
