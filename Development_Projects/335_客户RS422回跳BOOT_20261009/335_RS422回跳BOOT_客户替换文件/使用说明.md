# 335 客户 RS422：SCI-A 收到请求后跳 BOOT

交付：rs422.c、rs422.h。保留原 GBK 编码。替换客户原 rs422(1).c（或工程内的 rs422.c）及 rs422.h；不要同时编译两份。

## 保留与新增

保留 SCI-A / SCI-B 的 baud 入参、37.5 MHz LSPCLK 计算、8E1、FIFO、GPIO、中断入口，以及 VMC/CCDL 的缓冲区、计数、标志和发送函数。SCI-B 不接收升级请求。

SCI-A 的 serial_RXA_isr 只读取一次 SCIRXBUF：原始值照常存入 VMC_RX_BUF，并旁路送入新增监测函数。合法请求只设置待跳转标志，不在 ISR 中跳转或阻塞等待，不发送应答、不实现查询/下载协议。

## 主循环必须接入

在现有主循环/周期任务的业务处理之前增加：

```c
if (RS422_BootPending())
{
    /* 使用客户原有停机流程：停止控制输出、DMA/业务任务及新增发送。
     * 停机必须完成后再调用下方函数，重复调用需安全。
     * 本次循环不继续安排新的业务发送。
     */
    RS422_BootTask();
}
else
{
    /* 原业务调度 */
}
```

上面的注释必须落实为客户现有停机动作；仅添加调用不能代替业务停机。没有收到请求时执行原业务调度。BootTask 检查 A/B 两路 TX FIFO 为空且 TXEMPTY=1；未发完时返回，下一次继续调用。它不检查客户软件发送队列，调用前必须停止新的发送调度。

## 请求

客户通信端使用 APP 实际波特率和 **8E1（偶校验）**，从 SCI-A 发送原始十六进制字节，不是 ASCII 字符串：

```text
CC 58 00 E9 00 72 00 00 00 0C 1E
```

沿用 V201 0x72 进入 BOOT 请求格式：长度为 11 字节，前 3 字节 CRC8（右移，0x8C，初值 0），前 9 字节 CRC16（右移，0xA001，初值 0），CRC16 低字节先发。示例序号为 0；序号改变时 CRC16 必须重算。响应帧、非 0x72 命令及校验失败帧不会设置请求标志。

SCI 原接收路径有奇偶/帧错误或 FIFO 溢出时，新增监测丢弃此前候选字节。监测是固定 11 字节滑动窗口；原业务帧解析文件未提供，因此没有业务帧边界识别和接收超时判定。必须将该完整升级请求保留为专用序列，不能允许它出现在业务载荷中，不能宣称任意两种协议绝对无冲突。该请求不带设备地址，同一链路多设备接收时需要客户通信端定向选通目标。

## 跳转与 BOOT

直接跳到现有 335 BOOT 的 codestart 0x33FFF6（C28x 字地址），不执行芯片复位。跳转前关闭 CPU/PIE 中断、保持两路 SCI 复位并禁止看门狗。未修改 BOOT，无 RAM 请求标志，也不修改 APP/BOOT 分区。

已有 BOOT 与 APP 分区需事先正确烧录/链接。进入当前 BOOT 后，它重新配置 SCI-A 为 **115200、8N1**。客户通信端在 APP 停机和跳转完成后释放链路，升级上位机切换到 115200、8N1，并在 BOOT 约 5 秒的监听窗口内发送有效升级握手；否则有效 APP 会自动重新启动。这版没有“必须一直停留 BOOT”的保证。

注意客户代码涉及外部 RS422 使能。文件只给出了 SCI_EN_Gpio_Init 调用，没有 gpio.h/gpio.c 和接线；必须实板确认跳转后收发器使能允许 BOOT 在 GPIO28/29 通信，否则只跳到 BOOT 也无法下载。
