# 335 APP 地址集中配置（2026-10-09）

默认 APP 起点仍为 0x300000（C28x 16 位字地址）。30 MHz / 33.3 MHz 的 BOOT、APP 和链接文件共用本目录的 UpgradeLayout.h。

## 使用

1. 在 UpgradeLayout.h 顶部选择一个 UPGRADE_APP_AT_xxxxxx 宏：取消目标行的 `//`，并给原先开启的行加上 `//`。只能开启一个，全部关闭或开启多个会编译报错。不用手动输入地址，也不要修改下方自动推导的 UPGRADE_APP_START。

   默认开启：
   ```c
   #define UPGRADE_APP_AT_300000
   // #define UPGRADE_APP_AT_308000
   ```
   例如改为 0x308000：
   ```c
   // #define UPGRADE_APP_AT_300000
   #define UPGRADE_APP_AT_308000
   ```
   可选项为 300000、308000、310000、318000、320000、328000、330000，对应 H/G/F/E/D/C/B 扇区。宏只按是否定义选择，关闭时请注释整行；写成 `#define ... 0` 仍算开启。

2. 重新编译对应晶振的 BOOT 和 APP。APP 的 BEGIN、FLASHAPP 起点和长度自动随公共配置变化，无需再手动改 .cmd；BOOT 写入、校验和跳转使用相同起点。
3. 用 JTAG 烧录新的 BOOT；统一升级上位机填写相同 APP 起点，再选择新 APP .out 升级。若更改分区后芯片仍保存旧 APP 有效标志，须先保持 BOOT 升级模式或同步烧录新 APP，不能让新 BOOT 根据旧标志跳入尚未下载的新入口。
4. 复制/导入 CCS 工程时保留完整 335_BOOT_APP 目录及公共头文件。原四套工程文件和引脚/晶振配置保留，不能只复制单个 boot 或 app 子目录。

V201 传输协议保持不变：上位机不发送起始地址，不能在运行时改变 BOOT 分区。现有用户版上位机可继续使用；仅改上位机地址不会改变已烧录 BOOT 的写入基址。

## 擦除

标志固定在 0x337FFE，APP 结束地址不包含 0x337FFE。BOOT 仍在 A 扇区；标志所在 B 扇区先擦除，之后按 APP 起点擦除到 C 扇区的剩余 APP 扇区。默认顺序保持原版 B、C~H；起点越后，前面的扇区越不参与擦除。

| APP 起点 | 后续 APP 擦除扇区 | 掩码（不含先擦除的 B） |
|---|---|---|
| 0x300000 | H/G/F/E/D/C | 0xFC |
| 0x308000 | G/F/E/D/C | 0x7C |
| 0x310000 | F/E/D/C | 0x3C |
| 0x318000 | E/D/C | 0x1C |
| 0x320000 | D/C | 0x0C |
| 0x328000 | C | 0x04 |
| 0x330000 | 无（APP 与标志同在 B） | 0x00 |
