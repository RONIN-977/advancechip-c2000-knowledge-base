1、 前言
在实际的调试中，经常会碰到 CCS 与仿真器连接问题，导致芯片无法正常烧录。本文档主要对
调试中常见的 CCS 与仿真器连接报错汇总，并提供相应的理论支持及排查方向。
当 CCS 连接不上芯片的时候，建议排查的方向如下：
 检查仿真器是否插好，可以反复插拔尝试；
 检查 DSP 供电问题，3.3V，1.8V 的供电是否正常；
 检查 DSP 引脚是否虚焊（一般检查 JTAG 相关引脚）；
 检查晶振是否起振；可排查 XCLKOUT 时钟输出频率；
 检查 JTAG 相关引脚电平是否正确，特别注意 TCK 是否有脉冲输出，以检测仿真器是否好坏；
 检查 DSP 上电是否正常复位；
 检查 CCS 路径的 FLASHAPI 文件是否替换；
 尝试降低烧录主频是否能正常烧录；

3、 检查复位引脚
 当芯片 FLASH 区域没有烧录进程序的时候，XRS 引脚是一个周期性复位的信号。复位周期为
芯片的看门狗复位时间。
 AVP32F335 看门狗模块如图 3-1 所示，当 8 位看门狗计数模块溢出，产生一个输出低脉冲。以
外部晶振 30M 为例，复位时间大约: 1/(OSCCLK/512) *(2^8) = 4.369ms。
 以我司 AVP32F335A_EVM REV2.0 开发板为例，外部晶振 30Mhz，复位电路 R=10K，C=0.1uF。
芯片的复位引脚波形如图 3-2 所示。复位周期为 9.3ms，幅值 3.3v。

4、 检查晶振
 可以通过示波器观察芯片系统时钟输出 XCLKOUT 引脚(PIN138)，来排查外部晶体是否启振。
此时时钟输出的信号是XCLKOUT = SYSCLKOUT/16 = 1.875Mhz和 XCLKOUT = SYSCLKOUT/16 = 
3.75Mhz 的频率相互切换。如图 4-1 所示。其中黄色 XRS，绿色 XCLKOUT，当 XRS 为高 XCLKOUT 
= 3.75Mhz，XRS 为低时 XCLKOUT = 1.875Mhz。
 芯片 CPU 的 CLKIN 来自外部晶体，当 XRS 为低时，PLL 为旁路模式，分频寄存器
PLLSTS[DIVSEL] = 0，CLKIN = XCLKIN/4。
 
 XCLKOUT 的信号直接由 SYSCLKOUT 产生，如下图所示。XCLKOUT 可以等于二分之一或四
分之一的 SYSCLKOUT。默认情况下，在芯片上电时，XCLKOUT = OSCCLK/ 4 或 XCLKOUT = 
OSCCLK/16。注意引导 ROM 发生了变化 SYSCLKOUT 从 OSCCLK/4 到 OSCCLK/2。因此，如果引
导 ROM 在复位后被执行，XCLKOUT 将是 OSCCLK/8。
 复位激活时，XCLKOUT 信号激活。由于 XCLKOUT 在复位低时应该反映 SYSCLKOUT/4，所
以您可以监视这个信号来检测设备在调试期间是否被正确地计时。XCLKOUT 引脚上没有内部上拉或
下拉。
如果 XCLKOUT 没有被使用，可以通过将 XINTCNF2 寄存器中的 CLKOFF 位设置为 1 来关闭
XCLKOUT。

5、 检查JTAG引脚
 JTAG 相关引脚的定义如下所示：
 AVP32F335 开发板 JTAG 电路如下，注意 TRST 下拉电阻 2.2K。5 脚 3.3 供电。
 排查方法如下：
1、万用表调到蜂鸣档测量线路通断，测量原理为检测红黑两表笔之间的阻抗大小，当测量的阻值
小于参考值（70~80Ω ），万用表蜂鸣。
2、检测芯片引脚是否损坏，万用表调到二极管档测量，芯片不上电。
3、使用万用表二极管挡位，红表笔测量芯片 IO，黑表笔测量芯片 VCC,如果有 0.3V-0.7V 左右的
电压，表示芯片内部的 IO 到 VCC 的保护二极管正常，如果电压为 0V，则此端口已被损坏。
4、使用万用表二极管挡位，红表笔测量芯片 GND，黑表笔测量芯片 IO,如果有 0.3V-0.7V 左右的
电压，表示芯片内部的 GND 到 IO 的保护二极管正常，如果电压为 0V，则此端口已被损坏。

6、 典型案例
6.1 ‘-260’（0xfffffefc）
 Test Connection 出现‘-260’错误码的时候，排查仿真器是否插到电脑 USB 口。
6.2 ‘-233’（0xffffff17）
Test Connection 出现‘-233’错误码的时候，排查 JTAG 相关引脚是否有断开情况，当使用隔
离仿真器而目标板的 3.3V（JTAG14PIN 的 5 脚）没有引出的时候，同样报-233 故障码。

6.3 ‘-230’（0xffffff1a）
 Test Connection 出现‘-230’错误码的时候，表示链路延迟或扫描路径存在错误，排查 1.8V 供
电情况。或供电的电源纹波。
6.4 ‘-151’（0xffffff69）
Test Connection 出现‘-151’错误码的时候，连接期间使用的某个 FTDI 驱动程序函数返回错
误状态或错误，排查仿真器型号是否正确。

6.5 ‘-1137 @ 0x06’
Test Connection 通过，但是烧录过程中出现 Failed CPU Reset:(Error -1137 @ 0x6)，排查烧录过
程中是否 XRS 复位引脚变为低，原因可能为供电能力不足导致电压跌落。
6.6 ‘-1156 @ 0x0’
 Test Connection 通过，但是链接芯片出现 low-power mode:(Error -1156 @ 0x0)，排查 JTAG 引
脚的 EMU0，EMU1 状态，如果使用的是我司 XDS100V1_REV2.0 仿真器，请去掉仿真器 R13，R14
电阻。再次尝试烧录。 
6.7 ‘-1015 @ 0x0’
Test Connection 通过，但是链接芯片出现 Device may be locked:(Error -1015 @ 0x0)，芯片可能
已经加密，检查程序的 CSM 区域是否写入了密码。

6.8 ‘-151@ 0x0’
烧录程序芯片出现 One of the FTDI driver functions used during the connect returned bad status or an 
error :(Error -151 @ 0x0)，排查仿真器配置文件的选型是否正确。
6.9 ‘Time out waiting for target’
 Test Connection 通过，但是烧录程序出现 Time out waiting for target to halt while 
executing FlashAPIInterface28335V2_10.out，替换我司 FLASHAPI。
 替换完成 FLASHAPI 还出现烧录超时现象，请降低烧录主频再次尝试烧录。

6.10 ‘烧写过程缓慢，停在某一段’
Test Connection 通过，但是烧写过程非常缓慢，停在其中某一段，烧写进程停止，
使用 CCS 的 halt CPU 功能停止烧写。检查 flash 编程电压是否正常，是否有硬件断点没有
去除。
