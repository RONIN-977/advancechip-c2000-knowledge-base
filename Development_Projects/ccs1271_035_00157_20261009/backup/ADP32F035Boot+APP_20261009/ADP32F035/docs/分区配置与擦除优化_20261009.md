# 035 分区配置与擦除优化

本次保留默认分区、ADP 专用 ROM Flash API、SCI/CAN 协议和 APP 返回 BOOT 路径。修正原实现将 APP 相对位置固定映射到扇区 H 的问题。移动 APP 起点后，不再需要改写 begin_image() 中的掩码计算。

## 修改分区

统一修改 `Common/partition_config.h`：

```c
#define PART_APP_START  0x3E8000UL
#define PART_APP_END    0x3F2000UL
#define PART_METADATA   0x3F2000UL
#define PART_BOOT_START 0x3F4000UL
```

均为 16 位 WORD 地址，结束地址不包含。四个边界必须按 0x2000 WORD 整扇区对齐；APP 不得覆盖元数据；元数据独占一个扇区并位于 BOOT 之前；至少保留扇区 A 给 BOOT 和顶部保留区。非法配置会触发编译错误。

`boot_core.h` 中的 BL_APP_START / BL_APP_END 和 `board_config.h` 中的 BOOT_METADATA 自动引用此配置，不再分别填写数值。

同时手动匹配链接文件：

- Application/application.cmd：BEGIN.origin = PART_APP_START，长度 2；APPFLASH.origin = PART_APP_START + 2，长度 PART_APP_END - PART_APP_START - 2。
- Bootloader/bootloader.cmd：BOOTFLASH.origin = PART_BOOT_START，长度 0x3F7F80 - PART_BOOT_START；BEGIN 固定在 0x3F7FF6，不能随 BOOT 区域起点移动。
- 在完成编译后运行 `python tools/verify.py`，核对地址宏与链接文件一致，并验证 ROM API 和 RAM 函数位置。

例如只把 APP 改为从 G 扇区开始：PART_APP_START = 0x3EA000；APP 链接 BEGIN = 0x3EA000，APPFLASH 起点 0x3EA002、长度 0x7FFE。其余默认值不变，上位机起始地址填 0x3EA000。

当前上位机只支持自定义起点，035 结束地址仍为 0x3F2000。若改变 PART_APP_END，还需同步上位机的结束地址支持；不能只改设备端。035 的 BOOT 位于高地址，APP 起点上移腾出的低地址空间并不会自动变成连续的 BOOT 区域。

## 擦写实现

`Bootloader/flash_layout.h` 按固定物理地址映射 H→A 的掩码，不依赖 APP 从哪个扇区开始。`begin_image()` 在任何标记失效或擦除前检查镜像，并计算完整的 APP / 元数据掩码，然后沿用原有失效、擦除、下载、校验和提交顺序。

元数据擦除不再写死 SECTORC。api_erase() 仅允许当前配置的 APP 与元数据扇区；BOOT、未使用扇区、掩码高位均不能被擦除。api_program() 只允许 APP 或 20 WORD 元数据记录，禁止跨区及写入二者之间的空隙。

新增 `boot_debug_flash_erase_mask` 记录最近实际调用 Flash_Erase 的掩码。默认完整 APP 为 0xF8、元数据为 0x04；APP 改到 G 后，短镜像应为 0x40，不再错误选择 H 的 0x80。

新增辅助函数与擦写调用函数均放入 ramfuncs，由现有初始化搬运。ROM API 库、地址校验和时序配置不变。

## 验证与实板步骤

- `python tests/partition_tests.py`：6 种合法布局，逐一覆盖各布局全部 4 WORD 倍数镜像长度；验证所有物理扇区、跨扇区、边界、溢出及写入限制；8 种非法配置应编译失败。
- `pwsh -File tests/run.ps1`：原有 SCI FIFO / 非 FIFO 和 APP SCI/CAN 返回 BOOT 回归。
- `pwsh -File build.ps1`：构建默认 BOOT、APP 和 SCI8 文件，保持 ADP 专用库校验。

本次优化已做软件回归及编译验证，仍需在板上验证新 BOOT：先用默认分区分别进行 SCI/CAN 升级；再使用隔离工程把 APP 移到 G，重新链接后下载，观察擦除掩码及 GPIO17，并验证再次升级。新 BOOT 需通过调试器下载。
