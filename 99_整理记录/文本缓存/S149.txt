1. 引言
TMS320F2802x、TMS320F2803x 和 TMS320F2806x 设备均属于 C2000™ Piccolo 微控制
器（MCU）平台，适用于嵌入式控制应用。TMS320F2806x 具备与 TMS320F2802x 和
2803x 设备相同的增强型控制外设，此外，2806x 还新增了以下功能：
• 直接内存访问（DMA）
• 维特比复杂数学与循环冗余校验单元（VCU）
• 多通道缓冲串行端口（McBSP）
• 高分辨率捕获（HRCAP）
• USB 控制器 + 物理层（PHY）
• 浮点运算单元（FPU）
• 额外的增强型正交编码器脉冲（eQEP）和增强型捕获（eCAP）外设
这些新增外设使固件工程师能够高效解决复杂的控制问题。
为便于迁移，可将这些设备分为两组：
• TMS320F2802x 和 TMS320F2803x，本文中统称 2802x/2803x
• TMS320F2806x，本文中统称 2806x
有关 2802x、2803x 和 2806x 系列当前可用的完整设备清单，请访问德州仪器官网：
http://www.ti.com/。
本文档的核心是描述两组设备之间的差异，仅针对应用程序在设备间迁移时需重点关注的领域
进行说明。有关各设备的具体功能详情，请参阅德州仪器官网（http://www.ti.com/）提供的设

2. 中央处理器（CPU）
2806x 设备是首款集成 C28x + 浮点运算单元（FPU）和维特比复杂数学与循环冗余校验单元
（VCU）的 Piccolo 设备（C28x+FPU+VCU）。基于 C28x+FPU+VCU 的控制器与德州仪器
现有 C28x 微控制器采用相同的 32 位定点架构，同时集成了与 TMS320x2832x/2833x 设备
浮点运算单元（FPU）类似的单精度（32 位）IEEE 754 浮点运算单元。它是一款高效的
C/C++ 引擎，支持工程师使用 C/C++ 开发系统控制软件和数学算法。部分 2806x 设备还集成
了独立于主 CPU 的控制律加速器（CLA），与部分 2803x 设备所采用的 CLA 相同。此外，
2806x 设备新增了维特比复杂数学与循环冗余校验单元（VCU），这是一个完全可编程模
块，与无 VCU 的 C28x 设备相比，可将通信类算法的性能提升高达 8 倍。
以下现有功能未做任何更改：
• C28x 指令集
• C28x 流水线
• C28x 仿真功能
• 内存总线架构
为支持浮点运算，标准 C28x 指令集新增了扩展指令。这意味着为 C28x 定点 CPU 编写的代
码与 C28x+FPU 完全兼容。C28x+FPU 的锁存上溢（LVF）和下溢（LUF）标志与外设中断
扩展（PIE）模块相连，极大简化了上溢和下溢问题的调试流程。有关 C28x+FPU 的入门介
绍，请参阅《TMS320C28x 浮点运算单元入门指南》（SPRAAN9）以及德州仪器官网提供
的在线培训课程《TMS320C28x 数字信号控制器 + 浮点运算单元》（网址：
http://focus.ti.com/docs/training/catalog/events/event.jhtml?sku=OLT107003）。
C28x+FPU+VCU 架构及指令集的详细说明请参阅以下参考指南：

3. 开发工具
2806x 提供了一套新的头文件和外设示例，其结构与 2802x/2803x 的头文件保持一致。
F2806x 头文件和外设示例包含在 controlSUITE 压缩包（SPRCA85）的 device_support 文件
夹中。
2806x 上的 C28x+FPU+VCU 需配合 Code Composer Studio™软件及 v6.0 或更高版本的
CodeGen 工具使用。请通过 Code Composer Studio 更新顾问获取后续更新。构建原生浮点
运算代码时，必须使用正确的运行时支持库，例如 C 语言使用 rts2800_fpu32.lib，C++ 语言
使用 rts2800_fpu32_eh.lib，这些库随编译器一同提供。
注意：为使 2806x 上的数学例程获得最佳原生浮点运算性能，建议使用 C28x FPU 快速运行
时库（SPRC664）。C28x 快速运行时库是一套针对带浮点运算单元的 C28x 的 C 语言程序
员优化的浮点数学函数集。计算密集型实时应用的设计人员无需重写现有代码，即可显著提升
执行速度。功能部分列出的函数均针对 C28x + FPU 控制器进行了专门优化。
注意：要使编译器生成原生 FPU 指令，需在 Code Composer Studio 中指定所使用的 C28x
设备带有浮点运算单元。需使用以下编译器开关：
-v28 --float_support=fpu32 在 Code Composer Studio 中，fpu32 开关位于运行时模型编译器
选项中。不可将未启用--float_support=fpu32 开关编译的代码与启用该开关编译的代码混合使
用，因为编译器针对浮点数的调用约定已发生变化。若尝试混合使用，链接器会报错提示目标
文件不兼容。若遇到此错误，请检查所有库是否均使用相同开关编译，尤其是编译器自带的运
行时支持库必须正确匹配。启用--float_support=fpu32 编译时，应使用 rts2800_fpu32.lib 或
rts2800_fpu32_eh.lib。
注意：要使编译器生成原生 VCU 指令，需指定所使用的 C28x 设备带有维特比、复杂数学和
循环冗余校验单元。需使用以下编译器开关：

-v28 --vcu_support=vcu32 在 Code Composer Studio v4.2.2 及以上版本中，VCU 开关位于

3.1 IQ_Math 与原生浮点运算之间的迁移
将 IQmath 格式编写的项目转换为原生浮点运算项目需执行以下步骤：
1. 在 IQmath 头文件中选择 FLOAT_MATH。该头文件会将所有 IQmath 函数调用转换为对应
的浮点运算等效形式。
2. 向设备寄存器写入浮点数时，需将浮点数转换为整数；同样，从寄存器读取值时，需将其
转换为浮点数。两种情况下均需通过乘以转换系数实现，例如，将浮点数转换为 IQ15 格
式时，需乘以 32768.0，如下所示：
#if MATH_TYPE == IQ_MATH
PwmReg = (int16)_IQtoIQ15(Var1);
#else // MATH_TYPE 为 FLOAT_MATH
PwmReg = (int16)(32768.0L * Var1);
#endif
将 IQ15 值转换为浮点数时，需乘以 1/32768.0 或 0.000030518。
3. 要充分利用片上浮点运算单元，需执行以下操作：
a. 使用 Code Composer Studio 及 v6.0 或更高版本的 C28x 代码生成工具。
b. 告知编译器可生成原生 C28x 浮点运算代码，需使用–v28 --float_support=fpu32 编译器开
关。在 Code Composer Studio 中，float_support 开关位于编译器选项的 “高级” 选项卡中。
c. 使用适用于原生 32 位浮点运算的正确运行时支持库：C 代码使用 rts2800_fpu32.lib；支持
异常处理的 C++ 代码使用 rts2800_fpu32_eh.lib。
d. 建议使用 C28x FPU 快速运行时库（SPRC664）提升 sin、cos、div、sqrt 和 atan 等数学
函数的性能。快速运行时库应在常规运行时支持库之前链接。
4. 封装与引脚分布
两组设备不兼容引脚。任何需在两组设备间迁移的应用都需要重新设计电路板布局，以适配引

7. 存储器映射
两组设备的存储器映射基本相似，但存在本节所述的差异。
7.1 顺序访问随机存取存储器（SARAM）
本节重点说明 SARAM 存储子系统的主要差异：

=== PDF页 7 ===
• SARAM 容量增加：2802x 最多提供 6K×16 字的 SARAM，2803x 最多提供 10K×16 字，
而 2806x 最多提供 50K×16 字。
• 最大 SARAM 块尺寸为 8K×16：当前 SARAM 块的最大尺寸为 8K×16（L4 至 L8）。
• 新增 SARAM 块：2806x 设备保留了与 2802x/2803x 相同尺寸和地址的 SARAM 块 L0 至
L3，此外新增了 5 个更大的 SARAM 块 L4 至 L8。新增存储块便于代码和数据的分区管
理，例如，若代码中使用乘累加运算（MAC），可将操作码和两个操作数分别存储在三个
不同的存储块中，以实现最高效率。
• SARAM 块无双重映射：2802x/2803x 设备的 L0 存储块同时映射到高内存和低内存，而
2806x 的 L0 存储块无镜像映射。
• DMA 可访问 SARAM：L5-L8 存储块可作为 6 个 DMA 通道中每个通道的源和 / 或目标，
DMA 对 L5-L8 的访问无等待周期。2802x/2803x 不支持 DMA 功能。

7.2.2 Flash 访问时间
在相同频率下，2802x/2803x 和 2806x 的 Flash 访问时间相同。时钟频率高于 60 MHz 时的

7.2.3 Flash 的入口点与 CSM（代码安全模块）密码位置
两组设备的引导 ROM 入口点和代码安全模块密码位置均位于扇区 A 的最高地址处。
7.2.4 OTP 的入口点
两组设备的引导 ROM 进入 OTP 的入口点均为 OTP 的起始地址。
7.2.5 Flash 编程
设备的编程方法保持不变。德州仪器为每个设备提供 Flash 应用编程接口（API），作为所有
编程解决方案的基础。F2802x/F2803x 设备的 Flash API 和编程算法不可用于 F2806x，需使
用新的 Flash API 对这些设备进行编程，但 Flash API 的函数原型保持兼容。
注意：Flash API 包含时序关键的延迟循环，这些循环必须在零等待周期内存中运行，以确保
时序准确性。
7.3 引导 ROM
两组设备的引导 ROM 加载程序几乎完全相同，本节重点说明差异部分。引导 ROM 的部分增
强功能包括：
• 引导 ROM 容量增至 32Kw
• 新增 ROM API 表，支持 Flash API 符号库
• 除 IQmath 表外，新增浮点数学表
注意：IQmath 表的存储位置已发生偏移，请在链接器命令文件中使用新地址，具体可参考
controlSUITE 压缩包（SPRCA85，解压至 C 盘 v1.9.1 版本）中的 C2806x C/C++ 头文件和
外设示例。
7.3.1 引导 ROM 存储位置
2802x/2803x 和 2806x 设备的引导 ROM 保留内存均为从 0x002000 开始的前 80 个字。在引
导加载完成前，请勿向这些存储位置分配代码或数据。
2806x 设备的 OTP_KEY 位于地址 0x3D7BFB（2803x 设备为 0x3D7BFE），OTP_BMODE
位于地址 0x3D7BFE（2803x 设备为 0x3D7BFF）。
7.3.2 引导模式选择
2806x 设备的引导模式选择与 2802x/2803x 相比存在细微差异：2802x/2803x 设备的
OTP_KEY 校验值为 0x55AA，而 2806x 设备的校验值为 0x005A。

8.4 SYSCLK2 控制
2806x 新增了额外的系统时钟（SYSCLK2），作为支持 HRCAP 和新 USB 模块的时钟源，
该时钟由额外的 PLL（PLL2）提供，并新增了多个寄存器用于配置此时钟：
• PLL2 配置寄存器（PLL2CTL）：用于启用 / 禁用 PLL2 并选择时钟源（默认选择 X1）。
• PLL2 乘法器寄存器（PLL2MULT）的低 4 位（PLL2MULT）允许将 PLL2 设置为 0 至 15
之间的任意乘法器值，功能与 PLLCR 对 PLL 的控制类似。
• PLL2 锁定状态寄存器（PLL2STS）中提供了一个只读状态位（PLL2LOCKS），用于判断
PLL2 是否已锁定。

9.1.1 直接内存访问（DMA）
直接内存访问模块提供了一种无需 CPU 干预即可在 peripherals 和 / 或内存之间传输数据的硬
件方式，从而为其他系统功能释放带宽。此外，DMA 还能够在数据传输过程中对数据进行正
交重排，并在缓冲区之间实现乒乓传输。这些功能有助于将数据组织为块，以便 CPU 进行优
化处理。
DMA 模块是基于事件的设备，需要外设中断触发才能启动传输。六个 DMA 通道中每个通道
的中断触发源可单独配置，且每个通道都有其独立的 PIE 中断，用于通知 CPU DMA 传输已
启动或完成。DMA 的主要功能包括：
• 六个通道，每个通道在 PIE 向量表中均有独立中断
• 触发源包括：
◦ 模数转换器（ADC）中断 1 和 2
◦ McBSP 发送和接收
◦ 外部中断 1-3
◦ CPU 定时器
◦ ePWM1-6 转换启动（SOCA、SOCB）
◦ USB 端点发送和接收

• 短距离雷达复杂数学计算
• 功率计算
• 内存和数据通信数据包校验（CRC）

9.2 控制律加速器（CLA）
2806x 的 CLA 与 2803x 设备的 CLA 类似，两组设备的 CLA 寄存器组完全相同，CLA 控制寄
存器和 CLA 消息 RAM 的存储地址也保持一致。2806x CLA 的增强功能包括：
• 2806x CLA 的最高工作频率可达 80 MHz（2803x CLA 的最高工作频率为 60 MHz）
• 2806x 的 L0 RAM 作为 CLA 数据 RAM2 连接至 CLA；L1、L2 和 L3 RAM 与 2803x 设备
相同，分别作为 CLA 数据 RAM0、CLA 数据 RAM1 和 CLA 程序 RAM
◦ CLA 内存和时钟配置寄存器（MMEMCFG）新增了一个位，用于启用 CLA 对数据
RAM2 的访问
◦ MMEMCFG 寄存器新增了额外的位，允许 CPU 对每个 CLA 数据 RAM 进行写访问
（除读访问外）
• 2806x CLA 内核支持 DMA 访问
除 2803x CLA 可访问的 ADC 结果寄存器、比较器寄存器和 ePWM + HRPWM 寄存器外，
2806x CLA 还可直接访问 eCAP 和 eQEP 寄存器。相应地，2806x CLA 外设中断源选择寄存
器（MPISRCSEL1）的位定义已更新，包含了来自 eCAP 和 eQEP 模块的中断源。
9.3 高分辨率捕获（HRCAP）
2806x 的 HRCAP 模块能够以数百皮秒的典型分辨率捕获脉冲宽度，并执行常规和高分辨率
的时间差测量。
HRCAP 的应用场景包括：
• 电容式触摸应用
• 脉冲序列周期和占空比的高分辨率测量
• 瞬时速度测量
• 瞬时频率测量
• 读取隔离边界的反馈信号
• 距离 / 声纳测量和扫描

9.4 增强型控制外设
eCAP、ePWM、HRPWM 和 eQEP 模块的功能保持不变，两组设备的寄存器组完全相同，每
个外设实例的寄存器存储地址也保持一致（例如，2802x/2803x 上的 ePWM1 寄存器与
2806x 上的 ePWM1 寄存器地址相同），且 PIE 向量表中的中断向量位置也完全一致。PIE
向量表中新增了用于额外外设实例（如 eCAP3、eQEP2 等）的中断向量。此外，这些模块还
新增了以下功能：
• 2806x 设备配备 3 个 eCAP 模块（比 2802x/2803x 多 1 个）
• 2806x 设备配备 2 个 eQEP 模块（比 2802x/2803x 多 1 个）
• 2806x 设备最多配备 8 个 ePWM 模块和 8 个支持 HRPWM 的通道（比 2802x/2803x 多 1
个）
• 2806x 设备配备 4 个 HRCAP 模块（见 9.3 节）
• 2806x 设备的 eCAP 和 eQEP 模块支持 CLA 访问
• 2806x 设备的 ePWM 和 HRPWM 模块支持 DMA 访问
9.5 通信外设
串行通信接口（SCI）、串行外设接口（SPI）和集成电路间（I2C）模块的功能保持不变，两
组设备的寄存器组完全相同，每个外设实例的寄存器存储地址也保持一致（例如，
2802x/2803x 上的 SCI-A 寄存器与 2806x 上的 SCI-A 寄存器地址相同），且 PIE 向量表中的
中断向量位置也完全一致。PIE 向量表中新增了用于额外外设实例（如 SCI-B）的中断向量。
为 2802x/2803x 的 I2C、SCI、SPI 编写的代码可直接用于 2806x。
2806x 的 eCAN 功能与 2803x 设备的 eCAN 相同，寄存器组也完全一致；2802x 设备无
eCAN 模块。
除 I2C、SCI、SPI 和 eCAN 外，部分 2806x 设备还配备了 McBSP 和 USB 模块（见 9.1

• 2806x 设备配备 2 个 SCI 模块（比 2802x/2803x 多 1 个）
• 2806x 设备无 LIN 模块
9.6 模拟外设

• ADCCTL2 寄存器中新增了一个 ADCCLK 分频器，该位（CLKDIV4EN）为 2806x 的 ADC
