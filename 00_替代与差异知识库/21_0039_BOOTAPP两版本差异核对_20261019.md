## 结论

两套同源。20261009 版主要将 APP 分区配置集中到 `Common/app_partition.h`，使源码和链接文件联动，并扩大 BOOT 默认可链接空间；BOOT 的 `begin_image()` 另增擦除前参数复核。APP 的全部六个 src 文件逐字节一致。20261009 版不包含客户 CAN-only 改造，仍同时使用 CAN/SCI，毫秒计数仍使用 Timer0。

## 实际差异

| 项目 | 独立工程版 | 20261009 版 |
| --- | --- | --- |
| APP 起始地址 | 分散在 boot_core.h、application.cmd 等文件 | Common/app_partition.h 中 APP_START_ADDRESS，当前为 0x090000 |
| APP 结束地址 | 0x0AF000，不包含 | APP_END_ADDRESS，当前仍为 0x0AF000，不包含 |
| 元数据扇区 | 固定 0x08F000 | APP_START_ADDRESS - 0x1000，默认仍为 0x08F000 |
| BOOT 可链接区间 | [0x080002,0x088000) | [0x080002,元数据地址)，默认 [0x080002,0x08F000) |
| 分区检查 | 固定配置 | 公共头检查 APP 起点 >=0x082000 且 <0x0AF000，并按 0x1000 WORD 对齐 |
| Flash 擦除入口 | begin_image 直接进入元数据和 APP 擦除流程 | 先复核 start、entry、count 与 APP 范围，再执行原流程 |
| 工程依赖 | BOOT 和 APP 各自独立 | 两者都依赖同级 Common，复制和导入须保持相对目录 |

地址均为 C28x 16 位 WORD 地址，区间右端不包含。旧版 0x088000 至 0x08EFFF 的预留空隙被新版纳入 BOOT 可链接空间；这不等于实际 BOOT 固件已经占满该区域。

### 对应文件

- 新版 `Common/app_partition.h:6`：APP_START_ADDRESS；第 8 至 17 行：终点、metadata、BOOT 空间计算与检查。
- 新版 `APP/application.cmd:1` 和 `BOOT/bootloader.cmd:1`：预处理包含公共头，链接 MEMORY 使用公共宏。
- 两工程 `include/boot_core.h:13`：BL_APP_START/BL_APP_END 改用公共宏；`include/board_config.h:37`：元数据地址改用公共宏。
- 新版 `BOOT/src/flash_port.c:137`：begin_image 新增 start/entry 必须等于 APP 起点、count 非零、4 WORD 对齐且不超过 APP 容量的检查。这是 Flash 回调入口补充复核，不代表旧版协议层没有镜像检查；boot_core.c 未变化。
- 两工程 `.cproject`：Debug/Release 的编译和链接搜索路径均加入 `../Common`；`.project` 链接公共头。原有编译器与库选项保持一致，XML 格式变化不计为逻辑变化。
- 新版 BOOT 没有旧 `NewTargetConfiguration.ccxml`，`.ccsproject` 删除 isTargetManual；这是调试配置交付差异。旧版 APP 的原版固件归档未在新版 APP 中保留，新版根目录另有 output。

## 使用含义

保持默认分区时，两者升级协议与 APP 功能相同。20261009 版方便后续修改分区：只改公共头的 APP_START_ADDRESS，然后重编 BOOT、APP，重新下载 BOOT，并同步上位机 APP 起始地址。旧 APP 固件不会因修改公共头自动重定位。

复制新版时保持如下目录：

```text
AVP32F0039/
  BOOT/
  APP/
  Common/app_partition.h
```

这套新版仍需按客户工程适配 CAN 邮箱、时基和初始化；不能把它等同于此前单独修改的 APP_CAN_ONLY。
