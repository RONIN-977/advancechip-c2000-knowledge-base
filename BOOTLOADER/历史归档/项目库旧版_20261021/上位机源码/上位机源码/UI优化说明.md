# UI 优化说明（2026-10-08）

默认窗口 800×620，可拖动缩放。界面只显示真实 SCI / CAN 通信方式，仿真留在后台自检。

## 使用

1. 双击客户运行版目录内的“统一升级上位机.exe”。请保留整个客户运行版目录。
2. 选择芯片和通信方式；启动及切换通信方式时自动检索。插拔设备后点击“刷新设备”。
3. 从下拉列表选择串口或 CAN 盒；CAN 通道从 0 开始，设备索引由所选盒子提供。
4. 选择配套应用升级文件。可点击“读取设备信息”测试通讯并核对设备状态；升级前无需先读取。
5. 点击“开始升级”，程序自动进入升级模式并下载。升级成功后固定发送原有复位／启动请求，界面不再提供勾选项。

“读取设备信息”收到并校验有效应答后，日志显示“与设备程序通讯正常，设备信息读取成功。”，同时保留型号、状态和版本信息。打开接口、超时或无效应答不会显示通讯成功。

SCI 模式下 CAN 参数及驱动文件变灰。AVP32F335 仅支持 SCI，固定 115200，原 V201 BOOT 要求不变。
未检索到设备时请检查连接、匹配的驱动及其他软件是否占用设备，然后刷新。
CAN 驱动优先使用随包版本；需要更换时点击“浏览”。检索只读取板卡信息，不启动 CAN 通道或发送报文。

文件区显示文件名、大小及加载状态，完整路径和校验信息可通过悬停或日志查看。
“清除日志”只清空显示，任务、进度及后续日志不受影响；需要留档请先使用“保存日志”。
“停止升级”请求停止传输，不能立即终止设备正在执行的 Flash 操作。等待设备完成当前操作后再重试。
升级完成、启动请求已确认和启动未确认分别显示；收到复位应答不代表已确认应用运行。

## 修改边界

显示型号为 AVP32F0039、AVP32F335、AVP32F0049、ADP32F035。仅改变显示名称，原协议身份及分区保持不变。
本次只调整界面调用顺序、按钮、日志和后台自检。AVP32F0039、AVP32F0049、ADP32F035 在同一连接调用原进入升级接口后继续原下载流程；AVP32F335 沿用原自动进入 BOOT 流程。进入失败或取消时停止，不开始擦写。
核心协议、固件解析、校验、重传、原串口/CAN 收发和模拟器源码与修改前一致，见验证记录/一键升级/source-audit.json。
原 32 位桥接的 serve/check 路径不变；新增独立 discover 入口。

## 后台验证命令

在客户运行版目录执行（不会打开实际通信设备）：

```powershell
.\统一升级上位机.exe --self-check-ui C:\Temp\ui-self-check.json
```

输出目录须事先存在。该入口执行后退出，不在正常界面提供仿真选项。
