段落7: 测试引脚

段落8: TEST1为芯片内核供电的输出引脚，TEST2为内核供电地，TEST1与TEST2中间的电压为芯片的内核电压，在 F28335 中，芯片内部测试引脚建议悬空。AVP32F335A版本中TEST1和TEST2之间建议接1uf的电容。

段落9: FLASH使用概述

段落10: AVP32F335 A所使用的 Flash 为宏力提供，该 Flash 的 Program 和 Erase 注入和释放电荷的时间是通过系统时钟计数来保证。计数值是按照系统 时 钟 50MHz为基准。 

段落11: 每次 Program 和 Erase 都会有回读校验，如果 Program 和 Erase 不通过，会重复 Program 和 Erase。频率过高时，一次 Program 和 Erase 不成功（冲放电荷时间不够），会导致多次 Program 和 Erase，可能会刚好落入中间状态，读出值不稳定（如下图）。如果频率过低，每次 Program 和 Erase 时间太长，可能会导致过 Erase 和过 Program 状态。

段落12: 因此建议使用CCS进行AVP32F335A版本的烧录时，将烧写频率降低至45-60Mhz。

段落30: 芯片供电及上下电时序

段落31: 与 F28335 类似，AVP32F335A 在芯片封装定义上同样支持双电源供电，即 3.3V 与 1.8 或 1.9V。与 F28335 不同，AVP32F335 内部增加一级 LDO，将外部输入 1.8V 或 1.9V 转换 1.65V供给到内核（其中寄存器地址 0x7016 控制数字内核供电，0x7100 控制模拟内核供电），用户不需要在工程中做补充配置。 

段落32: 器件的上、下电时序在原 F28335 产品的基础上，需考虑增加一级 1.8V 或 1.9V 转换 1.65V LDO 的影响。上电阶段，使 XRS 信号在 1.65V 电压达到至少 1.35V 后再被上拉至高电平。下电阶段，使 XRS 信号在 1.65V 电压达到 1.35V 前 8us 变为低电平。

段落38: ADC硬件及软件部分其他差异点如下：

段落39: （1）ADC控制寄存器 1（ADCTRL1）的 bit[3:0]位定义差异

段落40: AVP32F335 A版本的ADCTRL1 的 bit[3:0]与F28335不同，F28335这四位均为保留位，AVP32F335A版本的ADCTRL1 的 bit3 为 ADC 模块内置 LDO 的使能位，ADCTRL1 的 bit[2:0]为 ADC 模块内置 LDO 的输出电压配置位。

段落41: （2）ADC 速度差异

段落42: AVP32F335 A版本的ADC时钟主频 7.5MHz，采样率 3.75MSPS。

段落43: TMS320F28335的ADC时钟主频25MHz，采样率 12.5MSPS。

段落44: （3）ADCREFP 和 ADCREFM 引脚外接电容容值和电阻值差异

段落45: AVP32F335A版本的 ADCREFP 和 ADCREFM 引脚的外接电容如下图所示，容值为 10µf，外接电阻为22kΩ，如下图所示。F28335的电容值为2.2µf，电阻为22kΩ。

段落46: （4）ADCREFP 和 ADCREFM 基准电压上电时间差异

段落47: ADCREFP 和 ADCREFM 引脚外接 10µf 电容时，AVP32F335A版本的 ADC 带隙基准稳定的延迟时间最大为 10ms。

段落48: ADCREFP 和 ADCREFM 引脚外接 2.2µf 电容时，TMS320F28335版本的 ADC 带隙基准稳定的延迟时间最大为 5ms。

段落49: （5）外设帧 0（PF0）和 2（PF2）的 ADC 结果位置差异

段落50: AVP32F335 A版本的Peripheral Frame 2 (0x7108-0x7117)和 Frame 0 (0x0B00-0x0B0F) 都是左对齐，并且两个外设帧地址里面的结果寄存器的低 4 位（bit[3:0]）都是变化的值，进行运算时取高 12 位（bit[15:4]）结果即可。

段落51: F28335 Peripheral Frame 2 (0x7108-0x7117)为左对齐，低四位（bit[3:0]）为 0 值，Peripheral Frame 0 (0x0B00-0x0B0F)为右对齐，高四位（bit[15:12]）为 0 值。

段落52: 因此CPU或DMA访问ADC镜像结果寄存器时需要右移4位。

段落63: 总结

段落64: 以上是针对目前大部分用户在从 F28335 向 AVP32F335A版本 移植过程中可能涉及的差异、产生调试问题的总结。用户在进入产品测试前，应在软件及硬件上重点关注芯片晶振型号输入、ADC 基准、Flash 烧写程序及在线程序部分代码与 FLASH API 关联性、FLASH 存储地址分配差异性，以便快速实现工程移植。
