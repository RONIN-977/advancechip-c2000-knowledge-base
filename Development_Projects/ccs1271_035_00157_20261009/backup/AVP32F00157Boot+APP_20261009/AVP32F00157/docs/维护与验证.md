# 维护与验证说明

## 初始化与源码分工

Device/source/device.c、Device/include/device.h、Device/source/f280015x_codestartbranch.asm 取自 C2000Ware 5.05.00.00，保持 TI 原始初始化。Common/boot_io.c 按 DINT → Device_init → Device_initGPIO → Interrupt_initModule → Interrupt_initVectorTable 顺序调用，再初始化计时和通信。没有额外 PLL 重试框架。

定义 _FLASH 后，Device_init 按链接符号搬运 .TI.ramfunc，初始化 Flash，再设置系统时钟。CPU Timer0 使用 1 MHz 计数，实现通信超时和非阻塞闪灯；本例轮询运行，不开启全局中断。

| 文件 | 维护内容 |
| --- | --- |
| Common/board_config.h | 波特率、CAN ID、超时、LED |
| Device/include/device.h | TI 时钟配置；修改需同步 Flash API 频率 |
| Common/boot_io.c | GPIO、CAN、计时、APP/BOOT 跳转 |
| Common/sci_port.c | SCI 接收错误恢复、发送、诊断 |
| Common/boot_core.c / .h | 协议及升级状态机 |
| Common/update_service.c | SCI 帧解析、CAN 分片、应答和升级入口 |
| Bootloader/flash_port.c | RAM Flash API、擦写校验、元数据 |
| Application/main.c | GPIO35 非阻塞闪灯，轮询升级指令 |

APP 增加中断、DMA 或其他外设后，请在 jump_image() 补充相应停用操作。现有实现先完成 ENTER_BOOT 应答，再跳 code_start → _c_int00，重新建立目标镜像 C 运行环境。

## 内存布局

以下全部为 C28x **16 位 WORD 地址**，结束地址不包含。

| 区域 | 地址 | 用途 |
| --- | --- | --- |
| BOOT | 0x080000–0x087C00 | 扇区 0–30，入口 0x080000 |
| 元数据 | 0x087C00–0x088000 | 扇区 31 |
| APP | 0x088000–0x09FFF0 | 扇区 32–127，入口 0x088000 |
| 尾部保留 | 0x09FFF0–0x0A0000 | 遵照 TI 链接文件保留 |
| 请求 RAM | 0x0003F8–0x0003FC | 四 WORD，两个工程均保留 |
| RAMCODE | 0x008000–0x00A000 | Flash API 和忙期间执行函数 |
| RAMDATA | 0x00A000–0x00BFF8 | 数据，末尾保留空间 |

APP 最大 98,288 WORD，即 196,576 字节。设备 ID 为 0x28015701，板号 0x55505301，CPU1；主机和设备同时检查型号、分区、入口、长度和 CRC。

使用 FAPI_F280015x_EABI_v2.00.10.lib，整个库与 RAM 包装函数编入 .TI.ramfunc。初始化逐 WORD 检查搬运内容，并检查编程入口位于 RAM。保护掩码禁止 BOOT 扇区 0–30 擦写，代码不发整 Bank 擦除命令。

编程按 4 WORD 对齐，自动生成 ECC。BEGIN 先擦元数据，再擦所需 APP 扇区；FINISH 校验 APP CRC，写元数据头，最后写独立新 ECC 行上的提交标记。不反复编程同一 ECC 行清除有效标记。Flash 忙时执行路径留在 RAM；若超过 5 s 仍忙，停在 RAM 错误循环，避免返回不可读的 Flash。

TI F280015x 示例擦写完成后的 FSM 检查值为 3，API 返回成功值仍为 0。不要套用其他系列的 FSM 判断。代码与链接检查已经通过，真实擦写仍需实板验证。

## 通信与诊断

GPIO28 关闭模拟功能后配置 SCIA_RX、异步采样。接收逐字节检查线路错误，溢出或错误后恢复接收和帧解析；应答等待硬件发送完成才允许切换镜像。主机原有串口超时 HEX 日志保留。

CAN 使用 DCAN driverlib，GPIO4 TX、GPIO5 RX。对象 1 接收标准 ID 0x601，对象 2 回复 0x581。沿用主机 6 字节负载分片，检查 DLC、扩展帧和消息丢失状态。

BOOT 正常主循环 boot_debug_stage = 5；0xE1 为 Flash 初始化检查失败。

- boot_debug_flash_ram_ok：正常为 1。
- boot_debug_flash_status：API 返回值，0 成功；0xFFFC 为 RAM 地址/长度错误，0xFFFD 为搬运不一致，0xFFF0 为忙超时，0xFFF1 为状态清除失败。
- boot_debug_flash_stage：2 擦元数据，3 擦 APP，4 写 APP，5 写元数据头，6 提交。
- boot_debug_flash_address / boot_debug_flash_fsm / boot_debug_flash_detail：失败地址、FSM 及 TI 校验详情。
- boot_debug_sci_bytes / packets / replies / errors / overflows：完整变量名均使用 boot_debug_sci_ 前缀；分别为字节、有效帧、回复、错误、溢出计数。
- boot_debug_tx_failures、boot_debug_can_errors：发送失败及 CAN 异常计数。

请用对应源码编译的 OUT 加载符号调试，复现时一并保存主机完整日志。

## 可复现检查

在工程根目录运行 build.ps1。tools/verify.py 检查项目链接、入口、RAM API 和保留空间。tests/run.ps1 -NativeCompiler <zig.exe路径> 编译本机 C 模拟 DLL 和 APP 服务测试，并运行真实 C# 主机协议代码；需 .NET 10 SDK。默认使用 UDS_OriCode 下现有 UI 优化版源码，也可通过 -HostRoot 指定其位置；固件输出目录由脚本显式传入，不需要复制上位机工程。

发布版模拟 UI 检查：

```powershell
& '../UI优化版（源码+交付）_20261008/UI优化版（源码+交付）_20261008/上位机本低部署版/统一升级上位机.exe' --self-check-2800157 C:/temp/00157-ui-check.json
```

输出目录须预先存在。此入口验证 SCI/CAN UI 模拟升级和旧型号设置恢复，不访问真实设备。23 项协议回归包括真实 OUT 转 SCI8、边界、CRC、分片、丢 ACK 重试、取消和错误注入；APP 服务测试覆盖 ENTER_BOOT 校验、先 ACK 后跳转、发送失败重试和回 BOOT 后 INFO。

没有重新实机验证旧型号，也没有将软件模拟当作新板实测。TI 许可保留在 Device，主机依赖许可保留在 assets / licenses。参考本机 C2000Ware F280015x 的 Flash、LED 例程及 device_support 原始文件，以及 [TI 产品资料](https://www.ti.com/product/TMS320F2800157)。
