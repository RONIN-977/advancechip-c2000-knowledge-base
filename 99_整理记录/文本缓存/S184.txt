1 简介
CAN 控制器是一个串行通信控制器，根据 CAN 协议执行串行通信。此 CAN 总线
接口使用基本的 CAN 协议，满足 CAN 2.0B 协议规范。该 CAN 内核也可以配置为满足
CAN FD 协议规范。
CAN 协议使用多主总线在网络节点之间进行帧传输，并进行错误处理，而不会给
CPU 带来任何负担。CPU 通过总线接口访问 CAN 控制器，CAN 通过 TX/RX 端口，在
CAN 内部协议机制控制帧的发送或接收。所有 CAN 节点在总线访问方面都是平等的。
没有超级节点，因为 CAN 是一条多主总线。
CAN 总线的连接如图 1 所示。

2 CAN 协议说明
CAN FD 是 CAN 2.0 的扩展协议，二者的主要区别在于：在数据传输负载方面，
CAN 2.0 最高 8 字节，CAN FD 最高 64 字节；在数据传输速率方面，CAN 2.0 有一个可
配置的比特率，而 CAN FD 有两个，仲裁过程慢，数据传输快；

3 特性说明
 支持 CAN 规范
 CAN 2.0B(最高 8 字节的有效荷载)；
 可选支持 CAN FD（最高 64 字节的有效荷载）；
 可编程数据传输速率
 CAN 2.0B 1Mbit/s；
 CAN FD 受收发器和 CAN 控制器的时钟频率影响；
 可编程带宽波特率分频(1~1/256)；
 主机接口和 CAN 协议有独立时钟域；
 可配置的接收缓冲区（RB）
 64 个 RB；
 类似 FIFO 功能；
 接收到的“不被接收的信号”或者“不正确”的消息不会覆盖已存储的消息；
 两个传输缓冲器
 一个主传输缓冲区(PTB)；
 可选可配置的辅助传输缓冲区（STB）；
 63 个 STB；
 可配置在 FIFO 模式或优先级模式下的操作。
 独立可编程的 29 位内部接收滤波器；
 扩展特征
 单次发送模式(发送 PTB 或/和 STB)；
 侦听模式；

标志，写 0 无效。

 接收完成的中断标志 RTIF.RIF；
 接收 RBUF 溢出的中断标志 RTIF.ROIF；
 接收 RBUF 全满的中断标志 RTIF.RFIF；
 接收 RBUF 几乎满的中断标志 RTIF.RAFIF；

7 传输模式
7.1 功能说明
传输模式包括单次传输模式、回环模式、侦听模式和待机模式。
单次传输模式下无论使用 PTB 还是 STB 如果发生错误或仲裁丢失将不再执行重新
传输。单次传输模式下，如果对 STB 使用 TSALL 全部传输，则对 STB 中所有帧进行
单次传输，STB 为空则停止。
回环模式包括内部(LBMI)和外部(LBME)两种回环模式，两种模式都能接收到自己
发送的帧。LBMI 模式下 CAN 控制与 CAN 总线断开连接，可用于芯片内部测试，LBME
与 CAN 总线保持连接，可测试收发器及其连接。
侦听模式提供了仅监测但不影响总线的功能。
待机模式下不可进行帧传输，节点可通过发送帧进行唤醒，如果所有接收节点都处
于待机模式时，发送节点会发生 ACK 错误。

9 发送帧
9.1 功能说明
发送帧有 2 种发送方式，一种通过配置 PTB、STB 传输的方式发送；另一种通过
TTCAN 定时触发发送的方式发送。
9.1.1 配置 PTB/STB 发送
TBUF 缓存分为两个传输缓冲区(TB)。主要缓存(PTB)具有更高的优先级，但只能缓
存一个帧。次要缓存(STB)的优先级较低，可以选择在 FIFO 模式或优先模式下工作。PTB
和 STB 之间的优先级决定是固定的，完全独立于 CAN 总线仲裁。总线仲裁是基于帧的
ID 优先级决定。
可以命令 STB 传输一个或所有存储的帧。在 FIFO 模式下，每次传输都会先传输
STB 缓冲区内先缓存的帧。在优先级模式下，首先传输缓冲区内优先级最高的帧（基于
帧 ID）。
不管帧 ID 是什么，位于 PTB 中的帧对于 CAN 控制器来说总是比 STB 中的帧具有
更高的优先级。PTB 传输停止并延迟 STB 传输。PTB 帧传输成功后，会自动重启 STB
传输。高优先级的帧不会中断正在传输的帧。
PTB 传输在 CAN 控制器下一个传输位置开始（在下一个帧间空隙之后）。所以正

9.1.2 传输中止
在传输尚未开始前，主机可以通过设置 TPA 或 TSA 来撤回传输请求并中止消息，
通过这种方式避免了传输缓冲区中的消息由于优先级低而无法发送，长时间占用缓冲区
而造成阻塞。
传输中止，只能中止还未传输的帧，并不是还未传输完成的帧，具体描述如下：
 如果帧成功传输，则不会执行中止；
 CAN 节点没有接收到响应而传输失败后，错误计数器将递增，并执行中止；
 如果 STB 中还剩下至少一个帧，而主机已经配置发送所有帧（TSALL＝1），
则向主机发送已完成帧以及中止信号。
如果执行中止会出现以下情况：
 配置 TPA，中止 PTB 传输将释放 PTB 且 TPE=0，但是帧数据仍然在 PTB 中。
 配置 TSA，中止 STB 传输，将释放一个或所有 STB，这取决于传输是由 TSONE
还是 TSALL 启动的。TSSTAT 将相应的更新。被释放的 STB 帧数据将丢失，
因为主机无法访问。

11 接收帧和滤波
11.1 功能说明
在 CAN 网络中，只有一个节点可以传输具有特定标识符(ID)的报文。所有节点接
收报文，节点主控制器必须决定它是否由适当的消息标识符寻址。为了减少主控制器的
负载，在接收帧的过程中，通过使用接收滤波器，检查报文的 ID 是否匹配滤波 ID，每
个接收滤波器的长度为 29 位，一共有 16 个滤波器。
CAN 帧的标识符也用于 CAN 总线仲裁。当具有较高优先级标识符的报文由另一个
CAN 节点传输时，CAN 协议机停止具有低优先级标识符的报文传输。CAN 协议机器自
动尝试在下一个可能的传输位置重新传输被停止的报文。
只要一条报文通过了其中一个过滤器，那么它将会被接收，并且将报文存入到RBUF
中，如果设置了接收中断使能 RIE，则 RIF 会被置位。如果报文不被接收，则不设置
RIF，RBUF 槽的指针不会增加。未被接收的报文将被丢弃，并被下一条报文覆盖。存
储的有效报文不会被任何未接收的报文覆盖。

13 错误
CAN 控制器内部有错误处理机制，不但能够自动消息重新传输和自动删除收到的
错误信息，并且还能给出错误类型标识和错误计数的值。
13.1 错误的状态和种类
CAN 控制器有 3 种错误状态信息，具体如下。
 主动错误：节点在检测到错误时自动传输主动错误帧；
 接收或发送错误计数小于 128；
 主动错误状态是可以正常进行 CAN 总线通信的状态；
 主动错误如果没发现错误，真个总线也被认为没有错误；
 被动错误：易引起错误的状态；
 接收或发送错误计数大于 127；
 虽然进行 CAN 总线通信，但会发送错误通知。
 总线关闭状态

计数分频器
PSC 加载 TDDR 的内容，计数寄存器 1。
PSC 可以通过读取寄存器来检查，但不能直接

其值。
