# 0039 KB CAN 在线升级软件仿真报告

日期：2026-10-19

## 结果

17 项测试全部通过。当前 KB 的真实 APP OUT 可经统一上位机核心完成 CAN 升级软件流程；写入 Flash RAM 模型后的全部 WORD 与固件镜像逐字一致，整包 CRC 正确，并完成有效镜像提交。

- 被测工程：BOOT_KB 与 APP_KB，工程名均带 _KB。
- 被测固件：APP_KB/Debug/F280039C_Application_KB.out。
- 实际镜像：3696 个16位WORD，即7392字节；入口和起点0x090000；CRC32为0x0C8BDD78。
- 正常镜像由上位机分为62个 DATA 包；请求和应答均执行实际 C 的 CAN 重组或分片逻辑。
- 最大容量测试为126976 WORD，即248KiB，末包为16 WORD；全量逐字读回一致。
- 测试未修改 BOOT_KB/APP_KB 工程或固件，没有生成压缩包。

## 实际执行的代码

1. 当前上位机源码 host/Updater.Core 的 Firmware、Protocol、Updater、TiOutConverter 等代码，按字节一致的快照编译；未使用界面的模拟模式替代它。
2. 最新 BOOT_KB/src/boot_core.c 原文件，执行请求校验、会话、重试缓存、状态机、CRC和CAN重组。
3. 最新 APP_KB/src/upgrade_entry.c 原文件，执行CAN轮询、请求识别、dispatch及成功应答后的复位请求调用。
4. 从最新 APP_KB/src/boot_io.c 原样提取 can_wait_tx 和 boot_send_reply，执行应答分片和等待完成逻辑。
5. TI hex2000 转换本次真实 APP OUT，并由上位机 TiBootTable 解析。工具参数 --sci8 用于生成TI字节启动表，并不表示升级使用SCI。

## 仿真边界

本次为实际 C 与 C# 代码的本机联测，不是执行 C28x 指令的芯片仿真。Flash 数组、ECC单元重复写入限制、CAN驱动寄存器、毫秒计数和复位/跳转由模型提供。BOOT main 的上电启动策略、真实 Flash_port.c 和 F021 Flash API 不在该运行模型中执行；实际 APP OUT 作为升级数据导入，不执行其C28x机器指令。

因此不能据此确认10MHz晶振起振、PLL锁定、真实CAN采样/波特率/仲裁/丢帧、Flash API时序/ECC/NMI、掉电保持、RAM升级标记跨复位保持及实际启动跳转。此前CCS编译和时钟宏检查结果仍有效，实板完整升级尚待验证。

模型复位只验证在对应调用点发生预期模式切换；不冒充真实watchdog复位、RAM cookie保持或codestart执行。

## 故障注入含义

故障1至4分别使Flash模型的begin、program、verify、commit回调失败，验证真实协议状态机拒绝提交有效镜像。故障5令CAN发送请求长期不完成，验证真实发送等待超时且APP不提前复位；时间由模型推进，不证明真实硬件定时。故障6丢掉请求中间一片，故障7交换中间两片，均由真实bl_can_feed处理。
