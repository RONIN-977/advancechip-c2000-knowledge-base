## 现象、定位及原厂结论

- 正文第 1 页（PDF 第 3 页）：50 套设备使用 50 颗芯片，2 颗偶发上电异常，客户描述约 20%（10 次中约 2 次）。这不是全系列失效率。
- 正文第 2–4 页（PDF 第 4–6 页）：报告记录供电、时序、BOOT 引脚、出厂 FT、Flash/PLL 参数和入口地址的排查。原板 RC 为 10 kΩ / 0.1 μF，XRS 低电平约 1.2 ms；延长保持及换 2.2 μF 仍未消除异常。GPIO84–87 原为悬空，加 4.7 kΩ 上拉仍复现。排除结论限定在报告测试条件内。
- 正文第 5–6 页（PDF 第 7–8 页）：模拟快上电（2–3 ms）下，两颗样品各 100 次测试出现 **21 次、13 次**启动异常；看门狗复位信号未产生。慢上电两颗各 100 次未异常。报告确认的故障路径是：快上电 WDFLAG 保持 1 → 仅依据状态位的二次复位分支被跳过 → 未规避 XINTF 上电复位 BUG → 访问 XINTF 扩展地址导致 CPU/PC 停住。
- 报告也记录同测试环境的 TMS320F28335 出现相同现象；这是该报告的参考试验记录，不能推导两者所有内部复位机制完全一致。
- 正文第 9–10 页（PDF 第 11–12 页）：原厂明确认为复位过程中无主动下拉会使看门狗标志未有效清零，导致程序漏掉复位动作；纠正措施是进入 `main()` 前，在启动汇编中引入 RAM KEY 辅助判断，保证上电二次复位。

## 修正方案及验证证据

正文第 7–8 页（PDF 第 9–10 页）的代码在 `DSP2833x_CodeStartBranch.asm`、C 运行库初始化入口 `_c_int00` 前处理：

1. 检查 WDFLAG；为 0 时进入复位路径。
2. WDFLAG 为 1 时继续检查 4 个 RAM KEY；任意不匹配也进入复位路径，不能仅凭 WDFLAG=1 继续启动。
3. 复位路径先写 KEY，再允许看门狗复位并原地等待；二次复位后条件满足才进入 `_c_int00`。

图片示例 KEY 从 **0x7F8** 起占 **4 个 16 位字（0x7F8–0x7FB）**，值为 `0xA5A5、0x5A5A、0x3210、0xFEDC`；WDCR 示例含 `0x0068、0x008B、0x00E8`，并操作 SCSR。这里只记录原图，不作为可直接替换任意项目的模板。实际移植要核对 CMD 保留区、复位保留性、Boot ROM/BOOT/APP 和 C 初始化对这段 RAM 的影响；长期断电、短时掉电残留 KEY、外部热复位等路径仍需目标板验证。

报告正文第 7 页：采用 64 bit RAM KEY 联合判断后，两颗异常样品快、慢上电 **各 1000 次未出现启动异常**；正文第 5 页另记录不使用 WDFLAG 作为唯一判断条件的初步改法，快、慢上电各 1000 次未复现。原厂用“完全规避/百分之百”描述纠正措施；本库保留为**该报告条件下已验证有效**，不扩展成所有型号/批次/电路的无条件保证。

## 后续诊断规则

- 区分“软件跳过看门狗复位分支”与“执行了复位配置但硬件没有触发”，同步观察启动标记、WDFLAG/KEY 与 XRS 波形。
- 延长上电 XRS 低电平的 RC 缓起，不等于程序已经运行后的热复位。新版勘误要求外部热复位需在进入 main 后触发；软件二次复位则在进入 main 前安排。
- 不能把所有冷启动异常归为 XINTF；先确认实际访问 XINTF、PC 停留地址及复位是否真的发生。
- 报告已经为该案例提供原厂正式判断，先前仅凭波形提出的“WDFLAG 导致跳过分支”现在有文档证据；其他客户项目仍按自身板卡和波形核实。
