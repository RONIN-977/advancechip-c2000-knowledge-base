描述 当对 FLASH 进行擦除和写入的时候需要降频。
应变方法 根据外挂晶振频率，调整 PLLCR 寄存器的值，改变时钟频率。
推荐频率
Flash program 和 erase 之前，Fsys<=150MHz
Flash program 和 erase 时，50MHz >=Fsys >=45MHz
Flash 唤醒时，Fsys<=50MHz
Fsys 为系统时钟频率

应变方法 通过程序降低 SCI 的采样波特率，延迟可能采样到的错误的开始位数据的第
四位，将此采样错误延迟到停止位的中间(远离信号过渡区域)。可通过所使

描述 ADC转换以同步模式启动时，第一个采样对不会给出正确的转换结果。
应变方法 1. 如果ADC的采样窗口≤160 nS，则必须丢弃第一个采样对，并采集同一对
的第二个采样。例如，如果排序器按该顺序设置为采样通道 A0：B0/A1：
B1/A2：B2，则使用 A0：B0/A0：B0/A1：B1/A2：B2 加载排序器，并仅使
用最后三次转换。
2. 如果ADC的采样窗口大于160 ns，则没有问题。 勘误项 ADC ：低频 ADC 不准确
描述 当 ADCCLK 频率低于 1 MHz 时，ADC 在某些器件上可能会给出不准确的结
果。在低温下，不准确性会更严重。较小的 ACQPS 设置（小于 3）更有可
能出现转换结果不准确。
应变方法 在 1 MHz 或更高频率下运行 ADCCLK 。
在低频下操作 ADCCLK 不会提高性能。建议将 ADCCLK 设置为数据手册中
指定的最大值或数据手册中指定最大值的一半。 勘误项 GPIO: GPIO 限定
描述 如 果 使 用 “ m ” 限 定 采 样 (m=3 或 6) ， 将 GPIO 引 脚 配 置 为 “ n ” 个
SYSCLKOUT 周期限定(其中 1 ≤ n ≤ 510)，则可能获得宽度为[n*m-(n-1)]的
输入脉冲限定(而不是 n*m)。这取决于异步 GPIO 输入信号相对于内部预分
频时钟的相位对齐，因此是不确定的。这种错误限定发生的概率是
“1/n”。

描述 在设置传输请求重置(TRR)寄存器位以中止消息后，在不设置中止确认(AAN)
位的情况下，TRRn 和 TRSn 位被清除的情况很少见。传输本身被正确中
止，但没有断言中断，也没有挂起操作的指示。
要发生这种少见的情况，必须满足以下所有条件：
1. 上一条消息不成功，要么是因为仲裁失败，要么是因为总线上没有
节点能够 响应它，或者是因为传输产生了错误帧。前一条消息不
需要来自当前正在尝试发送中止的同一邮箱。
2. 邮箱中 TRRn 位应在设置 TRSn 位的周期之后的一个 CPU 周期
内设置。由于传输未完成而保持设置的 TRSn 位也满足此条
件；即，TRSn 位可能已经设置，但传输仍未完成。
3. TRRn 位必须在精确的 SYSCLKOUT 周期中设置，在这个周期
中 CAN 模块处于空闲状态。当 CAN 模块不在接收/发送数据的
过程中时，称为空闲状态。
如果出现这些情况，则在设置 TRR 位后，邮箱的 TRRn 和 TRSn 位将在 tclr
SYSCLKOUT 周期内清除，其中：tclr = [(邮箱号) * 2] + 3 SYSCLKOUT 周期
如果出现这种情况，则不会设置 TAN 和 AAN 位。通常，在 TRR 位变为零
之后，TA 或 AA 位置位。
应变方法 发生此问题时，TRRn 和 TRSn 位将在 tclr SYSCLKOUT 周期内清除。要检
查这种情况，首先应禁用中断。设置 TRRn 位后，检查 TRRn 位 tclr
SYSCLKOUT 周期，以确保其仍被设置。TRRn 位置位表示未出现问题。
如果 TRRn 位被清除，这可能是因为消息的正常结尾，并且相应的 TAN 或
AAN 位被设置。检查 TAN 和 AAN 位。如果其中一个位置位，则不会出现
问题。如果它们都为零，则问题确实发生了。像中断服务例程一样处理这
种情况，只是 AAN 位现在不需要清除。
如果 TAN 或 AAN 位置位，当重新启用中断时，将会进入正常的中断例程。

勘误项 eCAN: 传输操作意外停止
描述 在极少数情况下，观察到来自 ECAN 模块的消息传输停止(同时接收操作
正常进行)。这种异常状态可能在没有任何错误帧的情况下出现在总线
上。
应变方法 可以使用 ECAN 模块的超时特征(MOTO)来检测这种情况。发生这种情况
时，设置并清除 CCR 位(使用 CCE 位进行验证)以消除异常情况。 勘误项 FPU：CPU-to-FPU 的寄存器移动操作，随后进行 F32TOUI32、FRACF32 或
UI16TOF32 操作
描述 当 CPU-to-FPU 寄 存 器 的 写 入 阶 段 与 F32TOUI32 、 FRACF32 或
UI16TOF32 指令的执行阶段重合时，该勘误项适用。如果 F32TOUI32 指
令的执行与 CPU-to-FPU 的寄存器写入操作发生在同一周期，则目标寄存
器（CPU 到 FPU 的寄存器写入操作）将被 F32TOUI32 指令的输出覆盖，
而不是被 C28x 数据写入总线上的数据覆盖。该场景也适用于以下指令：
 F32TOUI32 RaH, RbH
 FRACF32 RaH , RbH
 UI16TOF32 RaH , mem16
 UI16TOF32 RaH , RbH
应变方法 在使用 F32TOUI32、FRACF32 或 UI16TOF32 之前，CPU-to-FPU 寄存器的
写入之后必须有五个 NOP 或不冲突指令的间隙。
C28x 代码生成工具 v 6.0.5（针对 6.0.x 分支）、v 6.1.2（针对 6.1.x 分
支），以及更高版本都能检测到该现象。
问题示例：
SUBF32 R5H, R3H, R1H
|| MOV32 *--XAR4, R4H
EISQRTF32 R4H, R2H
UI16TOF32 R2H, R3H
MOV32 R0H, @XAR0 ; Write to R0H register
NOP ;
NOP ;
F32TOUI32 R1H, R1H ; R1H gets written to R0H

勘误项 FPU: 在任意 FPU 2P 操作之前的 FPU-to-CPU 寄存器移动操作
描述 当一个多周期 (2P) FPU 指令之后是 FPU-to-CPU 的寄存器传输时，该勘误
项适用。如果 FPU-to-CPU 读取指令源寄存器与 2P 指令目的寄存器相同，
则在 2P 指令完成之前，读取的可能是 FPU 寄存器的值。这是因为 2p 指令
在流水线的 E2 阶段依赖于结果的数据传输。如果流水线停滞发生在 E3 阶
段，则结果不会及时传输给读取指令。
受此勘误项影响的 2P 指令是 MPYF 32、ADDF 32、SUBF 32 和 MACF
32。FPU 寄存器必须读取 CPU 寄存器（ACC、P、XT、XAR 0…XAR 7）。
如果寄存器读取是 FPU-to-FPU 的寄存器传输，则此勘误项不适用。
在以下示例中，2P 指令 MPYF32 使用 R6H 作为目标寄存器。FPU 寄存器
也使用相同的寄存器 R6H 作为其源寄存器，并以 CPU 寄存器作为目标寄
存器读取 MOV32。如果在 E3 流水线阶段发生停滞，则 MOV32 将在
MPYF32 指令完成之前读取 R6H 的值。
问题示例：
MPYF32 R6H, R5H, R0H ; 2p FPU instruction that writes to R6H
|| MOV32 *XAR7++, R4H
F32TOUI16R R3H, R4H ; delay slot ADDF32 R2H, R2H, R0H
|| MOV32 *--SP, R2H ; alignment cycle

勘误项 eQEP: GPIO 异步模式下的 eQEP 输入
描述 如果通过 GPxQSELn 寄存器将任何 eQEP 输入引脚配置为 GPIO 异步输入模
式，则 eQEP 模块可能无法正常工作。例如，QPOSCNT 可能无法正确重置
或锁存，并且可能会错过输入引脚上的脉冲。这是因为 eQEP 外设假定模块
输入端存在与 SYSCLKOUT 的外部同步。
为使 eQEP 模块正常运行，输入 GPIO 引脚应通过 GPxQSELn 寄存器配置为
同步输入模式(带或不带限定)。这是重置时 GPxQSEL 寄存器的默认状态。
eQEP 模块输入引脚不应使用异步模式。
应变方法 将配置为 eQEP 引脚的 GPIO 输入配置为非异步模式(除“11b=异步”
之外的任何 GPxQSELn 寄存器选项)。 勘误项 eQEP: 在索引期间，位置计数器在方向改变时重置错误
描述 使用 PCRM=0 配置时，如果在索引输入有效时发生方向改变，位置计数器
(QPOSCNT)可能会错误重置，导致计数器值意外改变。这可能导致与位置
计数器的预期值相差最多±4 个计数，并导致随后意外设置错误标志。

使用 PCRM=0 配置[即索引事件上的位置计数器重置(QEPCTL[PCRM]=00)]
时，如果索引事件在向前移动期间发生，则位置计数器在下一个 eQEP 时钟时
重置为 0。如果在反向移动期间发生索引事件，则位置计数器在下一个 eQEP
时钟时重置为 QPOSMAX 寄存器中的值。EQEP 外设在 QEPSTS 寄存器中记
录 第 一 次 索 引 标 记 (QEPSTS[FIMF]) 的 出 现 和 第 一 次 索 引 事 件 标 记
(QEPSTS[FIDF])上的方向。它还会记住第一个索引标记上的正交边沿，以便
将相同的正交边沿用于索引事件重置操作。
如果在索引脉冲有效时发生方向改变，则模块仍将继续寻找用于执行位置计数
器重置的相对正交转换。这会导致位置计数器值发生意外更改。
应变方法 不要使用 PCRM=0 配置，如果在索引处于活动状态时可能发生方向更
改，并且由此产生的位置计数器值更改可能会影响应用。
如果适用于应用程序，用于执行位置计数器重置的其他选项[如索引事件
初始化(IEI)]则不存在此问题。 勘误项 eQEP: 第一个索引事件丢失
描述 如果 QEPI 输入的第一个索引事件边沿在相应的 QEPA/QEPB 边沿之前的一
个系统时钟周期到相应的 QEPA/QEP 边沿之后的两个系统时钟周期的任何
时间发生，则 eQEP 模块可能会错过该索引事件。这可能会导致以下行为：
• 如果 QEPCTL[PCRM]=00b 或 10b(在索引事件上重置位置计数
器或在第一个索引事件上重置位置计数器)，则 QPOSCNT 将不
会在第一个索引事件上被重置。
• 不会设置第一索引事件标记标志(QEPSTS[FIMF])。
应变方法 通过延迟索引信号以使 QEPI 事件边沿出现在相应的 QEPA/QEPB 信号边沿
之后至少两个系统时钟周期来实现可靠的操作。对于编码器可能给予 QEPI
信号相对于相应的 QEPA/QEPB 信号的负延迟(TD)的情况(即，QEPI 边沿出
现 在 相 应 的 QEPA/QEPB 边 沿 之 前 ) ， QEPI 信 号 延 迟 应 大 于 “ td +
2*SYSCLKOUT”。 勘误项 内存: 超出有效内存的预取
描述 C28x CPU 预取超出其流水线中当前活动的指令。如果在超出有效内存之外
进行预取，那么 CPU 可能会接收到无效的操作码。
应变方法 预取队列的深度为 8 x 16 字。因此，代码不应位于有效内存末端的 8 字以内。
