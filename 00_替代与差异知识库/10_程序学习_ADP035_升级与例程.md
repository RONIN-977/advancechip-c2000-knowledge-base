# ADP32F035：在线升级与开发板例程

更新时间：2026-09-23。**只覆盖定点 ADP32F035，不包含浮点 AVP32F035。**本轮静态阅读新补入的 UART/CAN BOOT 与 APP 工程、上位机说明，以及 `EVM_Project_Examples` 的 16 个示例；未用 CCS 重编译或上板测试。工程中的函数名和协议值是这套代码的实现，不自动代表其他版本。

## 在线升级：优先采用新补入的成套工程理解

新资料含 [UART BOOT](<../ADP32F035/Advchip上位机/Advchip上位机/AD032F035_UART/035/ADP32F035_BOOT_UART>)、[UART APP](<../ADP32F035/Advchip上位机/Advchip上位机/AD032F035_UART/035/ADP32F035_APP_UART>)、[CAN BOOT](<../ADP32F035/Advchip上位机/Advchip上位机/ADP32F035_CAN/035/ADP32F035_BOOT_CAN>)、[CAN APP](<../ADP32F035/Advchip上位机/Advchip上位机/ADP32F035_CAN/035/ADP32F035_APP_CAN>) 四个 CCS 工程和 [升级界面说明](<../ADP32F035/Advchip上位机/Advchip上位机/上位机/升级界面使用说明.docx>)。随包还带 AVP32F069 压缩包，本轮不把它当作 ADP035 证据。

| 层次 | 代码确认的流程 |
|---|---|
| 启动与返回 | BOOT 在 `Jump_Check()` 读取 APP 长度/CRC，整包 CRC 匹配且 RAM 升级请求标志未要求停留 BOOT 时，跳到 APP `0x3E8000`。APP 收到升级请求后设 `0x009FFE` 的标志，延时约 60 ms 跳回 BOOT。BOOT 在成功响应复位服务后也延时跳回 APP。入口见两套 BOOT 的 `main.c`、`dsp_program.c`。 |
| Flash 分区 | [BOOT 链接脚本](<../ADP32F035/Advchip上位机/Advchip上位机/ADP32F035_CAN/035/ADP32F035_BOOT_CAN/Library/CMD/ADP32F035_FLASH.cmd>)：BOOT 为 A+B（`0x3F4000` 起），C 扇区预留作 EEPROM，APP 为 D–H（`0x3E8000` 起）；D 扇区末尾 `0x3F1FFD–0x3F1FFF` 保存长度和 CRC。下载请求擦 D–H，逐块 `Flash_Program` 后 `Flash_Verify`，退出传输时再做 APP 全包 CRC16 比较，成功后写入长度/CRC。核心见 [dsp_program.c](<../ADP32F035/Advchip上位机/Advchip上位机/ADP32F035_CAN/035/ADP32F035_BOOT_CAN/UserCode/Com/Src/dsp_program.c>)。 |
| CAN 传输 | eCAN-A 用 GPIO30/RX、GPIO31/TX，500 kbit/s；标准帧 `0x7A0` 接收、`0x7B0` 应答，8 字节帧。协议层支持单帧、首帧、连续帧及流控帧；服务包括会话 `0x10`、种子/密钥 `0x27`、状态 `0x31`、下载/擦除 `0x34`、数据 `0x36`、CRC/退出 `0x37`、复位 `0x11`。见 [CAN 协议实现](<../ADP32F035/Advchip上位机/Advchip上位机/ADP32F035_CAN/035/ADP32F035_BOOT_CAN/UserCode/Com/Src/CAN_upgrade_protocol.c>)和 `can_config.c`。 |
| UART 传输 | SCIA 用 GPIO28/RX、GPIO29/TX；当前代码按 60 MHz 主频、15 MHz LSPCLK 配 BRR=15（约 115200 bit/s）。串口外层是 `FF FF + 类型 + 8 字节载荷 + 8 位累加和 + 0A` 的 13 字节帧；解析后把 8 字节载荷送入同一升级协议处理入口，所以源码注释称“物理层使用串口，数据层使用 CAN 的升级协议”。见 [UART 封装](<../ADP32F035/Advchip上位机/Advchip上位机/AD032F035_UART/035/ADP32F035_BOOT_UART/UserCode/Com/Src/uart_transfer_protocol.c>)和 [UART BOOT 入口](<../ADP32F035/Advchip上位机/Advchip上位机/AD032F035_UART/035/ADP32F035_BOOT_UART/UserCode/App/Src/main.c>)。 |
| 上位机 | 说明要求 APP BIN 按 128 字节分块，不满块补 `0xFF`，最后下发 CRC16；通过后芯片在 Flash 末尾写长度（word）和 CRC。支持 CAN/UART/LIN 的**上位机界面**，但这批 ADP035 MCU 源码只提供 UART/CAN BOOT/APP，不能据此宣称 ADP035 已有 LIN 在线升级工程。 |

这套工程的 10 MHz 外部晶振、PLL×12/2、`CPU_RATE=16.667 ns`、Flash `PAGEWAIT/RANDWAIT/OTPWAIT=2/2/3` 均按 **60 MHz** 配置，属于当前源码实际配置；不能直接当 100 MHz 的 ADP035B 工程。若移植到 B 版，需按当前 B 版资料重新处理时钟、Flash 等待、API 比例、定时器和通信速率，并核对芯片版本库。工程 `.cproject` 列出了 `Flash2803x_API_V100.lib`，但实际链接脚本 `Flash28_API` 段选用的是 `2803x_FlashAPI_BootROMSymbols.lib`，外部 API 函数体的两行已注释；不能仅凭库文件存在便判定当前工程调用 TI 函数体。如果以后改为链接外部 API 函数体，则须按 03x A/B 规则换成进芯对应版本。目录里有 `SFO_TI_Build_V6.lib` 也不证明升级程序调用了 SFO；若实际使用 SFO，仍须换进芯对应型号库。以上均未实机验证。

新包与旧 [ADP32F035在线升级.docx](<../ADP32F035/05_烧录与开发说明/ADP32F035在线升级.docx>)**不是同一份分区方案**：旧说明文字写 BOOT A、APP B–H，截图局部只显示擦 B/C；新包代码和链接脚本则是 BOOT A+B、EEPROM C、APP D–H。不能混烧两套 BOOT/APP，也不能把旧文档的截图当成新工程的擦除逻辑。旧文档引用的 `bootloader通信协议.xlsx` 本轮仍未见到；新包已有协议源码，可按新包追踪。

协议实现有几个复用前必须核对的边界：`0x34` 只对声明的**总长度**做上限判断，`Flash_App_Section_Write()` 本身没有再检查累计写入地址是否越过 APP 末尾；多帧接收用固定 256 元素缓冲，连续帧序号读取后未见比较预期序号；传输结束时的 CRC 只能校验最终内容，不能代替每帧边界检查。结论来自上述协议和写入函数的静态检查，是否能被上位机正常流程触发需联调验证。

## 16 个开发板例程

入口为 [EVM_Project_Examples](<../ADP32F035/EVM_Project_Examples>)。每个例程是独立 CCS 工程，不能因为共用支持库中含某外设源文件就认定该例程实际使用该外设。源码都采用外部 10 MHz 经 PLL 得 60 MHz，`CPU_RATE=16.667 ns`；以下是示例用途，不代表已在 B 版 100 MHz 上跑通。

| 示例 | 学到的实际用途 |
|---|---|
| [AD](<../ADP32F035/EVM_Project_Examples/Example_ADP32F03xAD/AD.c>) | ADCINB7 软件触发 SOC0–3，EOC3 触发中断并对 4 次结果平均。A 版 ADC 采样勘误需另按条件核对。 |
| [eCan](<../ADP32F035/EVM_Project_Examples/Example_ADP32F03xeCan/CANcomm.c>) | eCAN GPIO30/31 收发，500 kbit/s、8 字节，邮箱中断/外部 USB-CAN 测试；不是 CAN 升级。 |
| [Ext_Int](<../ADP32F035/EVM_Project_Examples/Example_ADP32F03xExt_Int/Example_ADP32F03xExt_Int.c>) | GPIO12 映射 XINT1，按键边沿中断翻转 LED。 |
| [Gpio](<../ADP32F035/EVM_Project_Examples/Example_ADP32F03xGpio/Example_ADP32F03xGpio.c>) | GPIO39 按键，GPIO13/14 LED，轮询与延时演示。 |
| [IIC_AIP650_SEG](<../ADP32F035/EVM_Project_Examples/Example_ADP32F03xIIC_AIP650_SEG/Example_ADP32F03xIIC_AIP650_SEG.c>) | I²C GPIO32/33 连接 AIP650，约 100 kHz，驱动四位数码管；AIP650 地址需按 7 位从地址处理。 |
| [IIC_EEPROM_AT24C02](<../ADP32F035/EVM_Project_Examples/Example_ADP32F03xIIC_EEPROM_AT24C02/Example_ADP32F03xIIC_EEPROM_AT24C02.c>) | 通过 I²C 读写外部 AT24C02，7 位地址 `0x50`，并提供串口指令演示；它不是片内 Flash 升级。 |
| [Lin_Buffer](<../ADP32F035/EVM_Project_Examples/Example_ADP32F03xLin_Buffer/Example_ADP32F03xLin_Buffer.c>) | LIN 外设设为 SCI buffer 模式，GPIO22/23、115200 8N1、8 字节收发；不是标准 LIN 协议升级。 |
| [PWM_AQ](<../ADP32F035/EVM_Project_Examples/Example_ADP32F03xPWM_AQ/Example_ADP32F03xPWM_AQ.c>) | ePWM7A/B GPIO40/41、约 10 kHz，对 AQ 强制输出与按键控制作演示。 |
| [PWM_DUTY](<../ADP32F035/EVM_Project_Examples/Example_ADP32F03xPWM_DUTY/Example_ADP32F03xPWM_DUTY.c>) | ePWM7 占空比按键调节、数码管显示；代码还写了 ePWM1–3 的 CMPA，移植时需核对是否为所需行为。 |
| [RS485](<../ADP32F035/EVM_Project_Examples/Example_ADP32F03xRS485/Example_ADP32F03xRS485.c>) | SCIA 接外部 SP3485 收发器，依赖开发板跳帽和收发方向控制；不是升级工程。 |
| [SCIA](<../ADP32F035/EVM_Project_Examples/Example_ADP32F03xSCIA/Example_ADP32F03xSCIA.c>) | GPIO28/29、115200 8N1，发送/接收中断和简单字符命令控制 LED。 |
| [SCIA_Printf](<../ADP32F035/EVM_Project_Examples/Example_ADP32F03xSCIA_Printf/Example_ADP32F03xSCIA_Printf.c>) | 将标准 `printf` 重定向至 SCIA，演示数值/字符串串口打印。 |
| [SPI_Flash](<../ADP32F035/EVM_Project_Examples/Example_ADP32F03xSPI_Flash/Example_ADP32F03xSPI_Flash.c>) | SPI 轮询/FIFO 访问外部 W25Q32，串口命令触发读写；这不是片内固件写入。 |
| [SPI_LoopBack](<../ADP32F035/EVM_Project_Examples/Example_ADP32F03xSPI_LoopBack/Example_ADP32F03xSPI_LoopBack.c>) | 实际 `main()` 配置 SPIA 内部回环并持续收发；文件头有 Spib/SPIA 混写，以实际调用为准。 |
| [Timer](<../ADP32F035/EVM_Project_Examples/Example_ADP32F03xTimer/Example_ADP32F03xTimer.c>) | CPU Timer0/1/2 中断周期分别配置为 1 s、100 ms、1 ms，Timer0/1 翻转 LED。 |
| [WD](<../ADP32F035/EVM_Project_Examples/Example_ADP32F03xWD/Example_ADP32F03xWD.c>) | 默认 `HWRST=1`，正常周期喂狗，按 K1 延时触发看门狗硬复位；也留有中断模式演示。 |

复用这些例程时，先核对 A/035B 版本、外部晶振、主频与 `CPU_RATE`、Flash 等待、GPIO 和开发板外设连接。对 ADP035B，现行差异规则中的 GPIO0/1 输入限制、TEST2 悬空、SFO 专用库及新增 L4 RAM 必须分别落实；详见 [差异学习笔记](<02_差异学习笔记.md>)。
