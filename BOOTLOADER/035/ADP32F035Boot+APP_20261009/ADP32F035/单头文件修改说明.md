# ADP32F035：只改一个头文件中的一行

唯一修改入口：`Common/app_partition.h`。

```c
#define APP_START_ADDRESS 0x3E8000
```

例如改为 `0x3EA000`。地址是 **C28x 16位 WORD 地址**，必须按 **0x2000 WORD** 整扇区对齐。

1. 完整解压工程，保持 Bootloader、Application 和外层 Common 的相对位置。源码和库已放进各自工程，外层 Common 只有共享地址文件。
2. 在 CCS 中导入两个工程，不勾选 Copy projects into workspace。
3. 打开任一工程树中的 app_partition.h，它们指向同一个实际文件，修改 APP_START_ADDRESS。
4. 对 BOOT、APP 均执行 Clean / Rebuild。**不需要手动改 .cmd、boot_core.h、board_config.h 或擦除掩码。**
5. 用 CCS/JTAG 下载重新编译的 BOOT；在上位机中填相同 APP 起始地址，加载新 APP OUT，点击开始升级。

源码和链接器直接包含同一头文件，未使用额外生成器。不要只编译一个工程，也不要使用 output 里针对默认地址的旧 OUT。
BOOT 链接空间不足、起点超范围或未对齐会报错；不要关闭这些检查。地址不会对旧 APP 二进制自动重定位。

035 BOOT 位于高地址。APP 起点上移只调整 APP 区域；BOOT 起点、元数据和 APP 结束地址保持原值。高级分区改动须同时核对 Bootloader/Common/partition_config.h 和 Application/Common/partition_config.h，并可能要求主机同步结束地址。普通 APP 起点修改仍只改共享 app_partition.h。

APP 结束地址维持 `0x3F2000`（不包含），与当前上位机匹配。修改起点不影响通信引脚、时钟、协议 ID 和 API 库。

验证：默认地址和示例新地址下，两工程均已实际导入 CCS 并编译；MAP 的 code_start 和 RAM 函数范围已核对。
测试变体相较默认版只修改 APP_START_ADDRESS 一行，没有修改链接文件。非法地址编译拒绝。本次联动改动仍需实板验证。

技术依据：[TI C2000 链接命令文件预处理](https://downloads.ti.com/docs/esd/SPRU513/linker-command-file-preprocessing-disable-pp-define-and-undefine-options-stdz0759758.html)。

当前独立工程版使用 CCS 12.7.1 / C2000 22.6.1.LTS；导入后选 Debug，执行 Clean / Rebuild。详见《独立工程与CCS12.7.1说明》。
