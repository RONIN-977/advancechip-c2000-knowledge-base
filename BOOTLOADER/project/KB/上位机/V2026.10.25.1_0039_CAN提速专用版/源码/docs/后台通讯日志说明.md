# 后台通讯日志说明（V2026.10.25.1）

本交付为0039 CAN专用界面，默认APP起始地址0x087000；读取设备信息和重启设备按钮隐藏，升级内部自动查询和复位仍执行。其他型号/SCI源码保留。

正常使用上位机即可。点击开始升级、读取设备信息或重启设备时自动创建一份日志，不需要另开监控工具，也不需要手动点保存日志。刷新设备沿用原检测流程，不额外发报文。

日志位置：便携版/Logs。目录不可写时回退到 %LOCALAPPDATA%/C2000Updater/Logs。界面会显示实际路径。日志只保存在本机，不上传。日志保留盒子序列号、驱动路径、文件路径、分区、时间及协议元数据，不保存固件内容。请按需要手动清理旧日志，程序不会自动删除。

每次操作两个文件：
- communication_时间_唯一编号.jsonl：详细记录，供排查；可用记事本打开，升级期间可后台读取。
- 同名.summary.txt：中文摘要，正常操作结束后生成，包含总耗时、各命令累计时间、重试次数、帧间等待及DLL调用时间。

测试方法：使用此版，选择原型号、CAN盒、波特率、通道、节点、APP起始地址和原固件，正常升一次。结束后提供同一时间的jsonl及summary.txt，即可分析耗时。失败或取消也保留日志。升级时不要直接关闭窗口；直接关闭/断电可能丢末尾排队记录且不生成摘要。

CAN详细指标：
- tx_dll_ms：VCI_Transmit调用累计时间；32位桥接时包含进程通信。
- pacing_ms：每帧实际等待累计时间，requested_pacing_ms为该命令目标间隔乘帧数。DATA目标1ms，控制命令仍为原WaitOne(3)。
- rx_dll_ms：接收DLL调用累计时间；包含等待及USB等开销，不能单独等同Flash擦写时间。
- rx_idle_ms：空读后原有2ms等待累计时间。
- txFrames/rxFrames/matchedFrames/decodedPackets：发送、收到、符合目标ID与帧格式、解出协议包数量。
- command_start/exchange_response/exchange_retry/command_failure：命令、会话、序号、尝试次数、返回状态和确认地址；BadState等错误原样记录。

统计之间存在包含关系：命令耗时包含CAN交换，不能重复相加。DLL发送成功只说明接口返回成功，不证明目标CAN确认；收到匹配的有效协议应答才说明本次往返完成。后台异步写盘，每包只入队事件，不逐帧打印。仍有少量测时/记录开销，实盒测速要使用同一版本比较。

ZLG和创芯共用诊断逻辑；本交付只显示0039 CAN，其他型号CAN路径代码保留。普通SCI记录协议交换及命令耗时；335 SCI维持原实现，只记操作/UI日志，不含逐命令和CAN明细。

本版DATA帧改为1ms相对高精度等待。若高精度定时器不可用自动降级为普通1ms等待（可能实际仍约15ms），日志pacing_mode显示legacy-wait-fallback。控制命令原WaitOne(3)、接收空读2ms、50ms接收参数、800ms入BOOT等待、重试次数和超时设置保持原值。BOOT、APP、分区及升级协议未修改。本机未自动启动升级，也未安装驱动。实测后看重试和超时是否为零；有重试或失败时先回退20261023日志版，保留两次日志对比。主机调用间隔不代表USB/CAN物理线上严格等间隔。
